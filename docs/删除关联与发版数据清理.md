# 删除关联与发版数据清理

2026-11-03 用户明确确认：每次线上发版清空全部用户的账本、计划、流水，保留账号。该规则通过正式部署脚本执行，不在服务启动或应用启动时执行。

## 删除语义

存款计划与存款账本是一对一的聚合。删除计划或关联账本时，在同一工作区锁和数据库事务内，将账本、类别、全部存入/取出记录、备注、目标及其他所属业务实体一并标记删除。普通账本、分类和记录同样按所有权删除子节点。共享标签或关系仅因被引用不会成为其他账目的所有者。

日常删除沿用回收站机制，不直接清空数据库。删除批次记录实际被本次删除的实体及其删除后版本；恢复计划时恢复同一批次，之前单独删除的子记录保持删除。禁止在账本仍被删除时单独恢复子记录，防止残留或错误余额。权限、版本冲突、资金约束校验失败时，整批回滚。已删除记录退出列表、统计与导出。

迁移 013 为历史已删除目标补齐账本和子节点的删除状态，修复旧版本仅删除目标却保留账本的情况。删除后允许以相同名称新建独立计划；旧目标不会继续占用新账本的唯一关联。

## 界面和名称规则

2026-11-03 最新要求：保留回收站与后台批次恢复机制，仅在 Web 端隐藏回收站、恢复按钮和恢复页面入口；原生移动端保留恢复，并提供独立的已删除计划页面及永久删除操作。删除确认不展示内部关联冲突等说明。

账本、存款计划、消费类别和流水内容允许同名或相同备注，每次新的创建操作生成独立 UUID。名称只用于显示；编辑、删除、切换和归属都通过 ID 关联。重复发送同一个 operationId 仍返回同一结果，防止网络重试造成重复账目。登录用户名等账号约束不受此规则影响。

## 计划永久删除

经方案确认新增迁移 015：仅已软删除的存款计划允许递归永久删除，包含所属账本及此前单独软删除的子记录。外部实体仅解除关联。清理过程使用事务、版本校验、权限与幂等保护；失败完整回滚，成功后不再提供恢复。同名重建使用全新 ID。接口及组件见[共享组件与存款计划删除流程](共享组件与存款计划删除流程.md)。

## 发版清理

正式入口：`server/ops/deploy-api.sh /opt/charge/releases/<release>`。

1. 准备并验证代码与独立测试库的集成测试。
2. 停止 API 写入，备份数据库，执行迁移。
3. 执行 `reset-release-data.sh`：再次生成完整备份，校验备份可读取，在事务中执行 `reset-business-data.sql`。
4. 清空所有用户的账本、分类、实际流水、备注、存款目标、计划账目、预算与调剂、模板实例、自定义配置及绑定、业务审计、回收站、导出任务和请求幂等记录。保留系统模板。
5. 保留账号 ID、用户名、密码哈希、角色、账号状态、会话、工作区和权限成员关系、系统设置与系统操作审计。保留工作区根 ID，设置手动记账初始状态。
6. 比对账号与成员数据，验证业务数据为空；任一检查失败则整个清理事务回滚。
7. 每个发布目录仅清理一次，与清理事务同时写入数据库 `release_data_resets`。另保存 `/var/lib/charge/release-resets/<release>.done` 文件供维护查看；即使文件丢失，数据库记录仍阻止二次清理。重复部署同一目录或服务重启不清除发版后新增记录。
8. 切换运行目录并启动服务，通过健康检查后交付 APK。

清理脚本仅供服务器维护使用，不提供普通用户 HTTP 清库接口；明确列出业务表，不使用 `TRUNCATE CASCADE`，避免连带清除账号。数据库备份保存在服务器 `/var/backups/charge/`，不会进入 APK。

当前开发阶段的全量清理是用户指定的发布策略。以后需要保留生产数据时，应先变更此策略与部署脚本。

## 验证

PostgreSQL 13 隔离数据库测试覆盖：计划删除与账本删除双入口、所有子记录和备注退出可见数据、同名重建、删除重试、越权和过期版本、恢复批次、保留之前删除的记录、阻止子节点越级恢复，以及准确运行正式清理 SQL、清理前后账号/密码/会话/工作区根/模板不变、清理后登录和重复清理。
