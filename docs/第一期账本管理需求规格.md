## 一、第一期目标与范围

交付一个通过HTTPS API访问PostgreSQL的 Android APK，让用户自行管理账本、分类树、收支明细、备注、标签、字段和实体关系，以树形组织数据，以平铺列表和图表查看整棵树或选定子树。

第一期包含支出账本和存钱计划账本。笔记管理统一显示“待开发”，不可点击；笔记、图片、个人日程与手机日历全部进入第二期。

默认不勾选模板，逐笔手动记账保持可用；另提供5种可选模板，用户选择、填写参数并自行命名即可创建。模板派生预算与计划，不自动生成实际收支。工资对照及预算支持真实 `.xlsx` 导出，详细规则见补充规格。

“灵活”具体落实为：业务结构可编辑、字段可扩展、标签可复用、关系可配置、查询范围可切换，同时保持数据完整性。

## 二、首页、抽屉与页面范围

### 2.1 模块首页

- 启动后进入模块选择首页，展示“账本管理”和“笔记管理 · 待开发”。
- 账本管理可点击，进入最近使用账本；无账本时显示新建引导。
- 笔记管理为静态禁用卡片，无点击事件、无可进入路由，无障碍状态标明禁用。
- 一期不提供可操作的笔记页面，不创建演示笔记冒充已完成能力。

### 2.2 全局侧边抽屉

每个页面顶部保留固定的切换按钮，点击即可弹出左侧抽屉，不依赖侧滑手势。

| 抽屉入口 | 行为 |
| --- | --- |
| 返回首页 | 回到模块选择 |
| 全部账本 | 查看完整账本树、搜索、新建、分组、排序 |
| 模板库 / 我的预算 | 选择系统或个人模板、命名、预览创建，管理月份方案及导出 |
| 支出账本 | 筛选此类型账本 |
| 存钱计划账本 | 筛选此类型账本与目标进度 |
| 全部明细 | 跨账本列表，展示明确账本类型和统计口径 |
| 计划账目 | 待执行、已完成、已取消的手动计划 |
| 标签管理 | 主分类标签、辅助标签及绑定关系 |
| 字段与关系 | 字段定义、选项、自定义关联配置 |
| 统计图表 | 当前范围、同层级、同标签聚合 |
| 笔记管理 · 待开发 | 禁用，不可点击 |
| 设置、备份、回收站 | 服务器数据管理与手机草稿 |

抽屉内部可切换当前账本，显示所在分组与账本类型。进入另一个账本后，当前账本页面刷新上下文；全局统计保留用户明确选定的多账本范围，并清楚展示。

编辑状态下打开抽屉不丢表单。真正跳转前持久化草稿；草稿不是正式账目，不计统计。草稿保存失败时阻止跳转并保留输入。Android 返回键优先关闭抽屉或弹层，再按路由返回。

### 2.3 必需页面

模块首页、账本树、账本新建编辑、分类新建编辑、明细列表、明细详情编辑、备注编辑、计划列表详情、存钱账本目标页、标签管理、字段管理、关系管理、统计页、模板库、模板参数与命名、创建预览、预算方案与执行、Excel导出、备份恢复、回收站、操作历史。

表单、详情和统计也属于“随时可打开抽屉”的范围。系统文件选择器等由 Android 接管的界面遵循系统导航，返回应用后恢复原状态。恢复替换数据库等临界操作显示忙碌状态，暂不执行破坏该操作的跳转。

## 三、多叉树及实体归属

### 3.1 节点与允许的父子关系

| 节点类型 | 可选父节点 | 可包含的子节点 | 用户操作 |
| --- | --- | --- | --- |
| 工作区根 | 无 | 账本分组、账本 | 稳定入口保留，可改工作区显示名 |
| 账本分组 | 根、其他分组 | 子分组、账本 | 增删改查、排序、移动 |
| 账本 | 根、分组 | 消费类型主标签 | 增删改查、排序、移动、归档 |
| 消费类型主标签 | 同账本的账本节点或其他主标签 | 子主标签、明细 | 增删改查、排序、移动、归档 |
| 收支明细 | 一个主标签 | 可选备注 | 增删改查、移动分类、查询来源 |
| 备注 | 一笔明细 | 无 | 增删改查，同一明细最多一条 |

分组与分类不设置固定业务层数，允许任意多个子节点。实现需检测循环与异常深度；极深结构可分段展开，不把界面渲染层数当作分类层数限制。

每个账本都是独立业务子树。账本下不嵌套另一本账本，需要组织账本时使用分组。每笔明细必须挂在分类下；创建账本可生成一个可改名、可迁移和可删除的“未分类”主标签，不强制永久保留。

一个分类下可以同时存在子分类和直属明细。备注是明细的可选附属节点，其内容也能在明细表单中直接编辑，不要求多次跳转才能填写。

### 3.2 一对一、一对多、多对多

| 关系 | 基数 | 含义 |
| --- | --- | --- |
| 父节点 → 子节点 | 1:N | 多叉树，非根节点只有一个父节点 |
| 账本 → 分类、明细 | 1:N | 明细账本由树路径决定，冗余账本 ID 必须一致 |
| 分类 → 直属明细 | 1:N | 每笔明细一个直属消费类型主标签 |
| 明细 → 备注 | 1:0..1 | 备注可选，最多一个 |
| 账本 → 目标配置 | 1:0..1 | 存钱账本一个目标配置，支出账本没有目标 |
| 主分类节点 → 分类标签定义 | 1:1 | 同一业务实体的结构与标签身份，不形成两份可独立漂移的分类 |
| 实体 ↔ 辅助标签 | N:M | 多实体、多标签绑定 |
| 自定义实体关联 | 1:1 或 1:N | 主树以外的附加业务关联 |

树路径与关系面板分别展示。关联另一个账本不会让一笔明细在两个账本下重复入账。

### 3.3 操作与追溯

- 支持新增、重命名、改描述与图标、调整顺序、搜索、移动、归档、删除及恢复。
- 提供表单式“移动到…”选择器；拖拽可以增强体验，但不是唯一操作方式。
- 详情显示完整面包屑，例如“个人 / 日常账本 / 餐饮 / 早餐 / 明细”，可点击查看每层。
- 移动分类子树时全部后代一起迁移，UUID 不变，附加关系继续按 ID 关联。
- 支持跨同类型账本迁移分类子树或明细，提交前预览数量、目标路径、命名冲突和字段约束。
- 跨账本迁移需校验币种、标签作用域、自定义必填字段、计划和来源分配关联，不能部分移动。
- 支出与存钱明细不直接跨类型移动，避免支出被误解为取出；需要关联时使用明确的来源关系。
- 节点不能成为自身或后代的子节点；同一父节点下分类规范化名称唯一，跨账本同名允许。
- 名称变化不改变 ID；不同账本的“交通”是不同主标签，不按名字自动合并。
- 操作历史记录关键字段前后值、移动前后路径、发生时间和操作类型，不能作为普通业务输入改写。
- 当前报表按当前分类树分组，明细发生日期不变；历史路径在操作历史中查看。一期不做按历史时点树结构重放全部报表。

## 四、两类账本与金额口径

### 4.1 支出账本

账本类型显示为“支出账本”，支持收入与支出两种方向。

账本字段：名称、类型、图标、颜色、说明、币种、排序、归档状态、自定义字段。明细字段：金额、方向、日期、直属主分类、可选备注、辅助标签、自定义字段、附加关联。

- 收入与支出都保存正数金额，用方向区分；月结余=月收入−月支出，不等于银行余额。
- 明确关联原支出的退款作为独立子类型，正常收入与退款分列，补充展示毛支出、退款、净支出；退款不重复计作工资收入。跨期退款的流水日期与原预算释放月份分别解释，实施细则见开发计划第四节。
- 使用整数分，按字符串解析金额，不用浮点数直接处理账务。最多两位小数，建议上限 999,999,999.99 元。
- 一期币种为人民币；内部币种码受支持范围约束，多币种转换不包含在一期。
- 实际明细日期不得晚于今天，未来事项使用计划账目。日期保存为本地自然日，审计时间保存 UTC 时间戳。
- 分类允许方向可由用户设为仅收入、仅支出或两者；修改规则前检查历史明细，不合规时先迁移或调整。

### 4.2 存钱计划账本

一个存钱账本对应一个目标，例如“买电脑”，包含目标金额、可选截止日期、说明。多个独立目标分别建立存钱账本，可放在同一分组下。

- 方向为存入、取出，全部手动更新，金额保存正数。
- 当前金额=有效存入−有效取出，不读取真实账户余额。
- 取出、删除存入或恢复取出后均不能导致当前金额为负。
- 进度=当前金额/目标金额，目标必须大于 0；允许超额，进度条封顶但文字显示实际比例。
- 修改目标不改变历史明细，到期不自动转账或完成。
- 起始存款通过“期初存入”明细记录，仍选择分类，不使用无法追溯的隐藏初始余额。
- 同样支持多层主分类、备注、辅助标签、自定义字段与关系。

### 4.3 跨两类账本关联

存入不是新增收入，取出也不一定等于消费。两类账本分别统计，不提供全部方向无差别相加的总金额。

存钱明细可选关联一笔支出账本的实际明细，说明资金来源或用途：

- 来源收入可对应多笔存入，分配合计不超过收入金额；来源支出可对应多笔取出，合计不超过支出金额。
- 一笔存钱明细最多关联一笔来源实际明细，也允许独立记录。
- 收入记账时可选择“分配到存钱账本”，同一事务创建存入明细及来源关联，各记录保留自己的树路径。
- 不强制把存入新增为日常支出，避免失真。
- 来源改方向、减金额、删除或迁移时预览影响，要求调整、解绑或阻止，不能保留超额分配。
- 解绑仅移除来源关系，不删除存钱明细。删除来源前明确选择如何处理关联记录，不静默级联删除。
- 这属于有金额约束的系统关系，自定义关系不能绕开分配上限。

例：收入 5,000 元并分配 1,000 元到“买电脑”，日常收入仍为 5,000 元，日常支出为 0，存钱增加 1,000 元，不能算成收入 6,000 元。

### 4.4 手动计划账目

- 计划选择账本和主分类，填写预计金额、日期、方向、标签、可选备注与自定义字段。
- 计划是独立实体，通过引用关联分类，在分类页“计划”分区展示，不混入实际明细树节点或金额统计。
- 预计方向遵守所属账本类型，计划备注也最多一条，可用计划附属字段持久化。
- 状态为待执行、已完成、已取消；逾期根据日期计算。
- 用户确认发生后，可改实际金额和日期，再原子创建明细、复制选定字段和标签、标记完成。
- 一条计划最多关联一条实际明细，不自动扣款或按日期记账。
- 删除恢复实际明细时同步处理计划状态，阻止重复执行与恢复冲突。

## 五、消费类型与实体标签

### 5.1 标签身份与作用域

| 类型 | 用途 | 关联方式 |
| --- | --- | --- |
| 主分类标签 | 属于某账本、组成分类子树，如餐饮 → 早餐 | 明细唯一直属父分类，父分类路径可追溯 |
| 辅助标签 | 跨树标签，如报销、旅行、家庭 | 全局或指定账本作用域，多实体绑定 |

主分类标签通过树管理，选择明细消费类型就是选择主分类；不能把多个主分类当普通标签同时追加。

辅助标签支持名称、颜色、图标、说明、适用实体类型、作用域。同一作用域内规范化名称唯一。账本作用域只适用于该账本、其子树和计划；全局标签可跨账本。

### 5.2 各实体的标签对应

| 实体 | 主分类关系 | 可绑定辅助标签 |
| --- | --- | --- |
| 账本分组 | 无 | 全局标签 |
| 账本 | 无，账本类型由字段决定 | 全局及本账本标签 |
| 分类节点 | 自身是主分类标签，可能有祖先分类 | 全局及本账本标签 |
| 实际明细 | 必须对应一个直属主分类 | 全局及本账本标签 |
| 备注 | 沿所属明细追溯分类与账本 | 全局及本账本标签 |
| 计划账目 | 必须引用一个主分类，不进入实际统计 | 全局及本账本标签 |

标签详情展示适用实体、直接绑定记录、数量与反向入口。删除标签先展示影响，软删除后不参与默认筛选；恢复时还原合法绑定。

### 5.3 查询与继承

- 默认按实体直接绑定标签查询，父节点打标签不静默改变全部后代的筛选结果。
- 提供“包含父级标签”开关；开启后按账本、分类及明细标签匹配，显示标签来源。
- 通过备注标签查询所属明细是单独开关，默认关闭；开启后按明细 ID 去重。
- 多标签支持满足任一或同时满足全部，默认任一，条件栏明确显示。
- 跨账本同主题使用同一全局辅助标签；同名主分类可搜索，但分组以 ID 为准。

## 六、自定义字段与表单

### 6.1 定义与支持类型

字段定义包括稳定 ID、展示名、适用实体、作用范围、数据类型、精度、是否必填、默认值、排序、校验、启用状态、是否在列表或筛选展示。

范围支持某实体类型的全局字段、某账本内该实体类型字段。两者同时适用时都显示，同名以来源区分，不按名称覆盖。

| 类型 | 示例 | 查询方式 |
| --- | --- | --- |
| 短文本、长文本 | 商户、用途 | 关键字、精确匹配 |
| 整数、小数 | 数量、里程 | 比较、区间；小数用定点值及精度 |
| 金额 | 预算、报销额 | 整数分、区间，不替代核心入账金额 |
| 日期、日期时间 | 报销日期、处理时间 | 区间，自然日与带时区时间分别处理 |
| 布尔 | 已报销 | 是、否、未填 |
| 单选、多选 | 支付方式、人员 | 稳定选项 ID，任一或全部 |
| 实体引用 | 关联账本、另一笔记录 | 关系定义及目标 ID，跳转与反查 |

实体引用复用关系表，不另存一份可漂移的值；核心金额等保留强类型业务列，自定义字段作为扩展保存。

### 6.2 增删改查与迁移

- 支持建字段、改名说明、调顺序、改默认、启用归档、查使用情况、删除恢复。
- 默认值仅应用于新建，不覆盖历史。
- 选填改必填先展示缺失记录并批量补齐；补齐前不启用破坏历史有效性的规则。
- 改类型或精度先在临时值上预览转换；不能转换则阻止，或另建新字段保留旧值。
- 删除先软删除定义并隐藏，不清空值；恢复还原字段和历史值，彻底删除展示影响数量。
- 删除选项保留 ID 与显示快照，旧值标注已归档，新建不可选；改名不改 ID。
- 跨账本迁移处理局部字段：映射到兼容字段、提升为全局或保留归档值，补齐目标必填值后整体提交。
- 隐藏不等于删除，删除也不能悄悄把所有值置空。

### 6.3 核心字段管理边界

用户可以编辑核心字段值、展示名、顺序、说明、非必填字段显隐。金额、方向、日期、归属、账本类型保留内部字段键与一致性校验；UUID、父链规则、审计记录和迁移版本不开放任意编辑。

删除备注或用户字段是正常操作，但不能把账务改成无金额、无方向或同时属于两个账本的无效记录。空账本可改类型；有数据账本一期不直接改类型，可新建目标账本并建立来源关联。

## 七、用户配置一对一、一对多关系

一期允许在现有分组、账本、分类、明细、备注、计划之间定义附加关系，不允许自定义任意实体种类。

本次增加预算方案和预算项作为系统定义的实体，复用标签、字段、关系基础设施。它们不属于实际交易，不能通过附加关系进入实际金额统计。

关系定义包括名称、正反向名称、来源/目标实体类型、1:1 或 1:N、适用范围、是否必选、删除策略、归档状态。

- 1:1：来源最多一个目标，目标最多一个来源。
- 1:N：来源可有多个目标，每个目标在该定义下最多属于一个来源。
- 必选属于最小基数规则，启用前校验已有实体并补齐。
- 同一实体对可用不同关系表达不同含义，同一关系不重复建边。
- 同类型来源目标一期不允许自关联；附加关系可形成业务网络，但不能替代树父链。
- 提供新增、查看、改名、改边、解绑、归档、删除与恢复，删除定义保留历史边。
- 从 1:N 改 1:1 先处理冲突，不随机保留其中一个目标。
- 来源与目标详情均显示关联入口。
- 必选关系定义启用前检测依赖循环，不产生无法创建或恢复的实体；支持在同一事务建立实体与必选边。
- 删除策略为有关系时阻止、或解绑且保留另一端，默认阻止；一期不允许任意级联删除另一端。
- 自定义关系不自动改变金额，只有明确实现的来源分配系统关系参与其专属校验。

例如“报销汇总明细 → 多笔原始消费”可设置为 1:N；不因建立关系自动生成报销收入，实际收支仍手动记账。

## 八、树形、平铺与统计

### 8.1 统一查询模型

列表、数字、导出和图表共用条件：树范围、是否包含后代、账本类型、实体类型、实际或计划、日期、方向、主分类、辅助标签及匹配方式、父级/备注标签开关、自定义字段、附加关系、关键字、归档状态。

默认统计只包含未删除且祖先未删除的实际明细。归档账本默认不列在可用工作列表，但可显式纳入历史查询；分类归档只禁止新增，不删除历史金额。计划视图不显示冒充实际统计的汇总。

### 8.2 三种视图

| 视图 | 行为 |
| --- | --- |
| 树形管理 | 展开、折叠、移动、排序，直属或全子树查看 |
| 平铺明细 | 指定树范围的明细放在一个列表，每行保留账本和路径 |
| 同层级管理 | 选择锚点及相对层数，查看该层节点并比较子树；支持兄弟节点视图 |

同层级按距锚点几层计算，不按名字猜测。跨账本可选择“各账本下第一级分类”。若某分类自身有直属明细，比较子分类时增加“直属明细”桶；较浅分支补充“未细分到该层”桶，不能漏账。

一期提供账本/分类批量归档与移动、明细批量移分类与加减辅助标签。批量操作整体校验、整体提交，失败说明原因，不静默跳过；金额不提供无预览批量覆盖。

### 8.3 聚合与去重

- 先取得唯一实际明细 ID 集合，再求和计数分组，不直接 JOIN 多标签后 SUM。
- 同时选父与子范围先合并，每笔只算一次。
- 账本、互斥主分类、日期分组可相加，组额与总额一致。
- 100 元明细同时贴旅行和报销标签，任一标签查询总额为 100 元，而非 200 元。
- 按辅助标签分别分组时可以出现旅行 100、报销 100，必须注明重叠，分组和不是净总额。
- 重叠标签分组用条形图/表格，不画伪互斥饼图，不擅自均摊金额。
- 饼图限同期间支出账本的互斥主分类占比，补足直属及未细分桶。
- 自定义字段支持筛选及单选、布尔等分组；多选分组遵循重叠规则。实际金额始终来自核心金额字段。
- 不同账本类型分面，不能将支出、存入、取出当成一个无差别总额。

### 8.4 图表清单

| 图表或指标 | 口径 |
| --- | --- |
| 收入、支出、结余 | 支出账本实际明细，结余=收入−支出 |
| 支出折线 | 日/月支出，空日期补 0 |
| 月度分类占比饼图 | 同期间主分类，支出为分母 |
| 同层级对比 | 显式相对层级的互斥子树，补足未细分桶 |
| 辅助标签对比 | 金额和条数，标注重叠 |
| 存钱目标进度 | 存入−取出，对比目标 |
| 存钱变化趋势 | 存入、取出和累计金额，独立于日常收支 |

点击图表项进入相同口径的明细，返回保留筛选。无数据、零分母、负结余分别处理。

## 九、数据库与实现约束

### 9.1 推荐表结构

| 表 | 用途及约束 |
| --- | --- |
| entities | UUID、实体类型、审计时间、软删除；标签与关系的外键目标 |
| tree_nodes | 同实体 ID、parent_id、排序，根唯一、父子类型白名单 |
| ledger_groups | 分组名称、说明和展示 |
| ledgers | 类型 expense / savings、币种、名称、归档 |
| category_tags | 分类节点扩展、账本 ID、名称、允许方向；与节点同 ID |
| transactions | 账本、主分类、方向、整数分金额、自然日、修订号 |
| transaction_remarks | 备注实体、唯一 transaction_id、正文，父节点须为该明细 |
| savings_goals | ledger_id 唯一、目标分金额、截止日期，仅用于存钱账本 |
| savings_source_links | 存钱明细 ID 唯一、来源实际明细，方向与金额分配校验 |
| planned_transactions | 计划实体、账本、分类、方向、预计值、备注、状态、唯一实际引用 |
| auxiliary_tags | 标签实体、作用域、适用实体类型、规范化名称、归档 |
| entity_tag_bindings | entity_id + tag_id 唯一，只绑定辅助标签 |
| field_definitions | 字段稳定 ID、类型、精度、作用域、校验、默认、展示、删除状态 |
| field_options | 选项稳定 ID、所属字段、名称、排序、归档、历史快照 |
| entity_field_values | entity_id + field_id 唯一，类型化文本/整数/定点/日期值 |
| entity_field_option_values | 实体、字段、选项唯一，多选单独建行并校验所属字段 |
| relation_definitions | 来源/目标、基数、作用域、必选、删除策略 |
| relation_edges | 定义、来源、目标，去重与基数约束、双向索引 |
| audit_events | 操作类型、前后值及路径、批次 ID，追加保存 |
| editor_drafts | 表单类型、实体、草稿值、更新时间，不计统计 |
| ledger_templates / template_instances / template_entity_mappings | 系统与个人模板、版本实例及模板行到实体UUID的映射 |
| budget_plans / budget_items / budget_revisions | 月份基数、受控派生规则、分类/储蓄去向与不可变修订 |
| budget_transfers | 从正余额tag扣除并补给负tag，记录来源/目标/金额/幂等批次/前后余额/撤销 |
| budget_usage_links / budget_transfer_operations | 交易到唯一预算桶的占用映射、显式储蓄占用、幂等操作状态与请求摘要 |
| transaction_refund_links / deletion_batches | 明确退款到原支出关联及额度限制、成组删除恢复 |
| app_settings / schema_migrations | 偏好、字段显示配置和迁移 |

全部可引用业务对象有稳定实体 ID，只有分组、账本、分类、实际明细、备注进入主树。标签、计划、字段定义、预算方案和预算项不伪装成实际明细树子节点，通过合法引用关联。

父链为事实来源，明细中的账本和分类冗余字段用于查询，由受控事务同步，不能让 UI 独立修改成不同归属。

### 9.2 必要规则

- PostgreSQL 外键、参数化 SQL、方向枚举、正数金额 CHECK 与唯一索引。
- 备注 transaction_id 唯一，清空可删除备注，明细保留。
- 根唯一，父子类型合法，检测循环，业务层与可执行数据库约束共同保证。
- 索引覆盖父节点排序、账本日期、分类日期、标签实体、字段值、关系两端。
- 排除被删除祖先下的记录，不只检查明细本身 deleted_at。
- 递归 CTE 取后代，验证深树与参数限制，不依赖超长 IN 列表。
- 路径/闭包表只作可重建索引，移动时事务更新。
- 用户字段不能提供 SQL 名称或片段，由稳定字段 ID 生成受控查询。
- 基数尽量用唯一约束或触发器保障，跨记录规则在服务端锁定工作区后的写事务重新校验。
- 金额、列表、CSV 与图表复用查询服务，不各自算一遍。
- 历史保存关键金额、分类、账本与用户字段前后值，不无限复制无关内容。

## 十、删除、恢复与备份

### 10.1 删除与归档

- 默认软删除，分组/账本/分类删除前展示子树及关联影响，可迁移后删或整子树入回收站。
- 后代、备注、字段值和绑定关系作为可恢复批次处理，不漏隐藏节点。
- 删除分类不留孤立明细，删除账本不能把明细留在全局统计中。
- 分类归档不移除历史金额，账本归档可显式纳入历史查询。
- 校验存钱非负、分配、计划状态和必选关系；不满足先处理，整批不得部分成功。
- 恢复检查父节点、同名、字段与关系；原父节点不存在则选择合法恢复位置。
- 原选项、标签或关系已失效时列出冲突并保留快照，不静默丢弃或改绑。
- 彻底删除预览影响并确认，默认不自动清空回收站；审计保留必要引用快照。

### 10.2 完整备份

数据库运维使用pg_dump自定义格式做一致性备份，包含schema、数据、迁移版本及完整约束，附版本、数量和SHA-256；一期无笔记附件。

- 包含树、记录、字段定义/选项/值、标签/绑定、关系/边、计划、目标、来源、模板、预算及修订、扣额、历史和设置。
- 管理员全库备份与普通用户单工作区数据导出分开；手机不得获得其他用户数据或整库身份信息。
- 完整恢复先在独立数据库校验，再安排服务切换；用户工作区恢复经API授权、暂存校验与影响预览。
- 迁移/恢复前保留原库快照，失败回退；未知更高schema拒绝导入，不能清库重建。
- 业务数据保存在所指定服务器；手机卸载只影响未提交草稿和缓存，重新登录读取服务端记录。
- 自动备份与异机副本须单独配置和演练，不把同一磁盘上的备份当作灾备已完成。

## 十二、性能与验证

建议数据集：30 个账本、50,000 条实际明细、至少 12 层分类分支、100 个字段定义、300 个辅助标签，以及同时命中多个标签的记录。另做更深树专项验证，确保检测及查询不会因界面递归崩溃。

选中端 Android 真机，发布构建目标为常用明细首屏约 500 毫秒内、汇总约 1 秒内；复杂跨树查询分页并显示加载。以固定设备与可重复数据集实测。

测试重点为树合法性与迁移、备注唯一、金额精度、字段转换、关系基数、来源分配、计划幂等、存钱非负、标签重叠、层级遗漏、删除恢复、备份与版本迁移。

一期完成标准为数据闭环和验收清单通过，并交付签名 APK、源码、schema/备份说明、操作指南与真机测试结果。笔记功能不作为一期上线依赖。

## 十三、注册与系统超级管理员

一期支持用户名/密码注册、登录退出、修改密码；注册固定普通用户并原子创建独立空工作区/根节点及owner关系，不自动套模板或造账。普通用户仅管理自己的数据，不能通过ID、筛选、下载地址访问他人数据。

系统超级管理员具有全部用户、工作区、账本树、账目、字段、标签、关系、计划、存钱、预算、模板、导出、回收站与配置的增删改查权限。管理操作复用业务规则与事务，显示数据所属用户，记录操作者、目标、理由与前后值。删除可恢复，相关扣额与审计历史保留。超级管理员不是PG SUPERUSER。

管理员可新建、修改、启停、重置密码、删除恢复用户和调整角色；任何时候至少保留一个有效超级管理员。停用/删除/改密/变更角色立即撤销旧会话；重置密码和首次管理员登录必须先改密。初始system_admin已在服务器创建，密码仅存服务端受限文件。

验收增加注册原子性、重名/角色伪造拒绝、跨账号授权、管理员对各业务实体完整CRUD、全局管理筛选、会话失效、最后管理员保护、审计及密码脱敏。详见[用户注册与超级管理员规格](用户注册与超级管理员规格.md)。
