# 个人笔记与记账管理 App 项目开发规划书

版本：V1.1 规划稿（补充笔记类型、个人日程、手机日历与手动插图）  
编写日期：2026 年 11 月 1 日  
交付平台：Android，最终交付可安装的 APK  
开发技术：Expo + React Native + TypeScript  
数据原则：业务数据保存在手机本地，核心功能完全离线运行

## 一、项目目标与产品定位

开发一款个人使用的移动应用，把关联笔记、个人日程、手动记账、账目计划和存钱目标放在同一个工具中，支持把日程一键加入手机日历。

应用需要同时解决四类问题：

1. **记录、关联与安排个人内容**：创建备忘录、日程规划、学习笔记等 Markdown 笔记，手动插入图片，通过内部链接和反向链接组织内容；在笔记中添加日程并一键写入手机日历。
2. **记录个人收支**：管理多个账本，在账本下维护收支分类，手动添加、修改、查询和删除每笔账目。
3. **查看财务情况**：按时间、账本和分类查看明细，展示收入、支出、结余、支出趋势和月度分类占比。
4. **追踪存钱目标**：创建有主题和目标金额的存钱计划，手动记录增加、减少，并允许与实际账单关联。

本项目优先保证数据正确、操作顺手、可备份恢复，再逐步增强笔记编辑和图表体验。首版不以完整复制 Obsidian 为目标，而是实现移动端最有价值的关联笔记能力。

## 二、需求解释与首版约定

以下是可以直接进入设计和开发的建议基线。涉及产品取舍的部分，在需求定稿时统一确认。

### 2.1 “计划账目”与“实际账目”分别保存

“需要计划每笔账目”按以下方式实现：既支持提前登记计划，也支持直接记一笔实际收支，全部由用户手动操作。

- **计划账目**：准备发生的收支，包含预计金额、预计日期、分类和备注。
- **实际账目**：已经发生并手动登记的收支，是统计图表的数据来源。
- 计划到期后只显示待处理提示，不自动生成实际账目、不自动扣款。
- 用户点击“确认发生”后，可以修改金额、日期和备注，再生成一条实际账目。
- 首版一条计划最多对应一条实际账目；分次发生、分期和周期计划放到后续版本。

“收入/支出”是**收支方向**，“待执行/已完成/已取消”是**计划状态**，两者不能使用同一个状态字段。

### 2.2 账本拥有自己的分类

- 每笔实际账目必须属于且只属于一个账本、一个分类。
- 每笔计划账目也必须选择一个账本和一个分类。
- 分类属于具体账本，分类方向为“收入”或“支出”。
- 例如“日常账本”的“交通”不能直接用于“旅行账本”，创建新账本时可以复制分类模板。
- 同一账本允许存在收入类和支出类的同名分类，但列表必须显示方向，避免混淆。

### 2.3 存钱计划是手动追踪工具

首版不连接银行、不推断真实账户余额，也不执行真实资金转账。

- 一个存钱计划绑定一个账本，包含主题、目标金额、可选截止日期和说明。
- 计划进度来自用户手动记录的增加、减少，以及显式关联账单的分配记录。
- 仅创建一笔收入或支出，不自动改变所有存钱计划；必须选择关联计划和分配金额。
- 存钱记录本身不再生成收入或支出，避免重复计入统计。
- 独立手动增加或减少可以表示已有存款的重新分配，不必强制创建一笔新的收支。

### 2.4 首版基础边界

| 项目 | 首版约定 |
| --- | --- |
| 使用者 | 单用户、单设备使用 |
| 货币 | 人民币，金额精确到分；账本保留币种字段，首版不开放多币种 |
| 时间 | 记账日期采用用户选择的本地自然日；创建与修改时间使用 UTC 时间戳 |
| 数据保存 | 本地 SQLite 数据库 + 应用私有目录中的附件文件 |
| 网络依赖 | 日常使用不需要网络，无业务后端和登录系统 |

| 笔记分类与状态 | 类型与处理状态分别管理；内置普通笔记、备忘录、日程规划、学习笔记 |

## 四、页面结构与关键交互

### 4.1 主导航

建议底部设置四个入口：**笔记、账本、存钱、设置**。

```text
应用
├─ 笔记
│  ├─ 笔记列表 / 类型与状态筛选 / 搜索 / 标签 / 文件夹
│  ├─ 笔记编辑与预览 / 手动插图
│  ├─ 日程卡片 / 日程编辑 / 一键加入手机日历
│  ├─ 今日日程 / 即将到来 / 已完成
│  └─ 反向链接 / 局部关系图
├─ 账本
│  ├─ 当前账本首页：本月概览 + 最近账单 + 待执行计划
│  ├─ 账本切换 / 新建 / 编辑 / 归档
│  ├─ 新增或编辑账目
│  ├─ 明细列表 / 账单详情 / 筛选
│  ├─ 计划账目列表 / 计划详情
│  ├─ 收支统计
│  └─ 分类管理
├─ 存钱
│  ├─ 当前账本的存钱计划列表
│  ├─ 计划详情 / 进度 / 记录明细
│  └─ 新建计划 / 增加或减少金额
└─ 设置
   ├─ 外观 / 默认账本
   ├─ 笔记类型 / 默认手机日历 / 权限说明
   ├─ 数据备份 / 导入恢复 / 导出
   ├─ 回收站
   └─ 应用版本 / 本地存储说明
```

账本和存钱页面共用“当前账本”。笔记属于全局笔记库，切换账本不会隐藏笔记。

### 4.2 记一笔账

1. 从账本首页点击“记一笔”。
2. 选择支出或收入，默认支出。
3. 输入金额，选择对应方向的分类。
4. 日期默认今天，可修改。
5. 按需填写备注。
6. 按需关联存钱计划，并输入分配金额。
7. 点击保存，在同一个数据库事务中保存账目和关联存钱记录。
8. 返回后立即刷新明细、统计和存钱进度。

金额、方向、分类是必填项；备注选填。输入错误时保留表单内容，并在对应字段说明原因。

### 4.3 提前计划一笔开销

例如计划 11 月 10 日支付交通费 200 元：

1. 在“计划账目”中新建支出计划，填写预计日期、分类、金额。
2. 11 月 10 日前显示“待执行”；超过预计日期仍未处理时显示“已逾期”。
3. 用户确认实际支出 186 元后生成实际账目，计划标记为已完成。
4. 当月支出统计只计入 186 元；计划金额 200 元只用于计划列表和预计汇总。

逾期是根据日期计算的展示状态，不自动触发扣款或生成账目。

### 4.4 创建关联笔记

1. 新建《旅行计划》，在正文输入 `[[旅行预算]]`。
2. 输入时提供已有笔记的标题候选。
3. 目标存在时点击跳转；不存在时允许创建同名笔记。
4. 《旅行预算》的反向链接区域显示《旅行计划》及引用片段。
5. 重命名《旅行预算》后，关联关系和相关引用一并更新。

首版支持整篇笔记链接，不承诺标题锚点、块引用、嵌入语法和 Obsidian 插件兼容。

### 4.5 在笔记中安排日程并加入手机日历

1. 新建《本周学习安排》，类型选择“日程规划”，也可以从已有学习笔记直接添加日程。
2. 点击“添加日程”，填写“复习 Expo 数据存储”、开始和结束时间，可选地点、提醒时间与简短说明。
3. 保存后在笔记详情中显示日程卡片，并进入应用内的今日或即将到来列表。
4. 点击卡片的“加入手机日历”。首次使用时请求系统日历权限，并让用户选择可写日历；优先推荐设备本地日历。
5. 首次设置完成后，再点击其他日程的添加按钮即可直接写入默认日历，不要求重新录入标题和时间。
6. 写入成功后显示“已加入手机日历”，按钮变为“查看日历事件”；笔记日程有修改时显示“更新手机日历”。

取消授权或取消操作时，日程仍在应用本地保存。写入手机日历属于用户主动导出，不会自动上传整篇笔记。

### 4.6 在 Markdown 中手动插图

1. 将光标放到正文指定位置，点击工具栏“插入图片”。
2. 选择相册、从文件导入或拍照；支持按需填写图片说明。
3. 应用复制图片到持久化附件目录，再在光标处插入 `![图片说明](attachments/图片ID.jpg)`。
4. 切换预览即可显示图片，点击可查看大图；之后可以修改说明、替换图片或移除图片引用。
5. 导出 Markdown 时同时导出其引用的图片，保持相对路径；备份恢复后图片仍可打开。

## 五、记账业务规则

### 5.1 账本管理

账本字段包括名称、图标、主题色、说明、币种、是否默认、是否归档。

- 首次启动创建一个“日常账本”和默认分类。
- 新建账本可以使用预设分类、复制已有账本的分类，或自行创建。
- 切换账本后，明细、计划、统计和存钱列表同步切换。
- 有业务数据的账本以归档作为日常移除方式；归档后可查看、可恢复，禁止新增记录。
- 有效账本至少保留一个，归档默认账本前需要选定新的默认账本。
- 首版不支持把一笔账目直接移动到另一个账本，避免分类、计划和存钱关联不一致。

### 5.2 分类管理

支出预设示例：餐饮、交通、零食、购物、日用、娱乐、住房、医疗、其他支出。  
收入预设示例：工资、奖金、兼职、礼金、其他收入。

- 分类字段包括名称、方向、图标、颜色、排序、是否归档。
- 新账目只能选择当前账本中未归档、方向匹配的分类。
- 分类改名后，历史账目显示新名称；金额和收支方向不变。
- 已被实际账目或计划引用的分类不能直接删除、不能修改方向，只能归档。
- 未被引用的分类允许删除。
- 同一账本、同一方向下，名称经过首尾空白清理后不得重复。

### 5.3 实际账目管理

必备字段：账本、分类、方向、金额、发生日期；可选字段：备注、关联计划、关联存钱分配。

- 每条记录的金额必须大于 0，方向决定其属于收入或支出。
- 首版金额上限建议为 999,999,999.99 元，最多两位小数。
- 数据库用整数“分”保存金额，计算与汇总使用整数，格式化时才转成元。
- 不直接使用浮点数处理财务运算；金额字符串按整数与小数位解析。
- 实际账目的日期不晚于今天，未来收支使用计划账目。
- 已发生日期保存为 `YYYY-MM-DD`，按本地自然日统计，避免时区转换造成跨日。
- 账目创建后可修改方向、分类、金额、日期和备注，但需重新校验所有关联记录。
- 删除账目进入回收站，立即退出统计，并同步撤销其关联存钱分配。

### 5.4 计划账目规则

计划字段：账本、分类、方向、预计金额、预计日期、备注、状态、关联实际账目 ID。

- 状态：待执行、已完成、已取消；“逾期”由待执行状态和预计日期计算。
- 确认发生时创建实际账目并更新计划状态，两步必须原子完成。
- 连续点击确认按钮只能生成一条账目，界面防重复与数据库唯一约束同时生效。
- 已完成计划通过关联的实际账目展示实际结果，原预计金额和日期继续保留。
- 删除关联实际账目时，计划恢复待执行；从回收站恢复账目时再次恢复完成状态。
- 已完成计划不可再次执行；已取消计划可手动恢复待执行。
- 如果在旧账目被删除后重新执行了计划，则禁止直接恢复旧账目，需先解决关联冲突。

## 六、统计设计与计算口径

所有统计默认限定在**当前账本、指定日期范围、未删除的实际账目**内。计划账目和独立存钱操作不参与收支统计。

| 指标 | 计算方式 |
| --- | --- |
| 本月收入 | 本月所有收入账目的金额合计 |
| 本月支出 | 本月所有支出账目的金额合计 |
| 本月结余 | 本月收入 − 本月支出；不称为银行卡余额或实际资产 |
| 支出趋势 | 按日或月聚合实际支出，无记录日期补 0 |
| 月度支出分类占比 | 当前分类支出 ÷ 当月全部支出 |
| 分类明细 | 某时间范围、某分类下的实际账目 |

### 6.1 图表交互

- **折线图**：默认展示当前月每日支出，可以切换近 6 个月的月支出趋势；点击节点显示日期和金额。
- **饼图或环形图**：默认展示当月各支出分类占比，显示分类名、金额和百分比。
- 分类较多时可将小项汇总为“其他”，点击后可展开查看组成。
- 点击分类跳转到明细页，并保留账本、月份和分类筛选。
- 明细中的收入、支出、结余汇总使用同一筛选条件，并明确显示当前条件。
- 没有支出时显示空态；不显示误导性的 100% 占比，不进行除零计算。
- 百分比显示的四舍五入差异可通过展示规则校正，底层金额保持原值。

### 6.2 数据口径示例

当月收入 5,000 元、餐饮支出 600 元、交通支出 200 元；另有未执行购物计划 300 元，以及独立增加存钱进度 1,000 元：

- 月收入：5,000 元。
- 月支出：800 元。
- 月结余：4,200 元。
- 餐饮占当月支出的 75%，交通占 25%。
- 购物计划 300 元不计入实际支出。
- 独立存钱操作 1,000 元只改变计划进度，不改变上述收支结果。

## 七、存钱计划详细设计

### 7.1 计划字段和展示

包含：主题、绑定账本、目标金额、可选截止日期、说明、主题色、状态。

- 目标金额必须大于 0。
- 当前金额 = 所有有效增加记录之和 − 所有有效减少记录之和。
- 进度比例 = 当前金额 ÷ 目标金额。
- 允许超过目标金额；进度条视觉上最多填满 100%，文字显示实际完成比例。
- 当前金额不得小于 0，减少操作超过当前金额时不允许保存。
- 降低目标金额不会修改既有记录，可能直接使计划达到目标。
- 状态建议分为进行中、已归档；“已达标”由当前金额与目标金额计算，减少后可以重新变为未达标。
- 到达截止日期只显示提示，不自动增加金额、关闭计划或生成账单。

### 7.2 两种手动更新方式

**方式 A：独立增加或减少。**

在计划详情中选择操作方向、金额、日期、备注。例如把已有现金中的 300 元计入“买电脑”计划，创建一条独立增加记录。

**方式 B：关联一笔实际账单。**

在记账时，或从账单详情中，选择“关联存钱计划”：

- 收入账单可把部分金额作为存钱增加。
- 支出账单可把部分金额作为存钱减少。
- 一笔账单可以分配到多个计划，分配总额不得超过账单金额。
- 账单和计划必须属于同一账本。
- 同一账单对同一计划最多保留一条有效分配记录，修改时更新原分配。
- 独立操作也可通过编辑转换成账单关联，但不能同时保留原记录造成双重增加或减少。

示例：工资收入 5,000 元，用户将其中 1,000 元分配给“买电脑”。月收入仍是 5,000 元，计划增加 1,000 元。后来消费 300 元并显式关联该计划，月支出增加 300 元，计划减少 300 元。

### 7.3 一致性与异常处理

- 修改账单金额时，必须重新校验分配总额；小于已分配金额时，要求先调整分配。
- 修改账单方向时，要求用户明确调整或移除现有存钱关联，不静默翻转增加、减少。
- 修改关联账单的发生日期时，同步更新其存钱记录日期。
- 删除账单时，在同一事务中软删除其存钱分配；恢复时重新校验计划状态、关联冲突和非负余额。
- 直接删除一条分配记录只撤销该计划的进度变化，不删除原账单。
- 删除一条增加记录可能导致计划余额为负，此时应阻止操作并提示先处理后续减少记录。
- 归档存钱计划后保持历史可查，新增和修改记录前需要恢复计划。
- 进度以有效明细记录计算，缓存不是事实来源；多计划分配须整体校验、整体提交。

## 八、笔记管理详细设计

### 8.1 编辑与组织

- 每篇笔记拥有稳定 UUID、标题、笔记类型、处理状态、Markdown 正文、创建时间和修改时间，可额外关联多条结构化日程。
- 支持标题、段落、列表、任务清单、引用、代码块、链接、图片等常用 Markdown 展示。
- 首版采用“文本编辑 + 预览”模式，提供常用格式工具栏；复杂富文本编辑器后置。
- 支持笔记列表、置顶、标签和文件夹；标签可多选，文件夹首版采用一层结构。
- 全文搜索覆盖标题和正文，标题匹配优先，结果显示摘要。
- 图片支持从相册、系统文件选择器和拍照手动插入，复制到应用私有目录，正文使用可导出的相对路径引用；具体见 8.8。
- 首版附件仅开放图片；任意文件、录音、OCR 和网页剪藏后置。
- 列表使用分页或虚拟化，避免一次渲染全部正文和图片。

### 8.2 内部链接与反向链接

建议支持 `[[笔记标题]]` 和 `[[笔记标题|展示文字]]` 两种语法。

- 为简化移动端链接选择，首版全库标题唯一；按统一规范处理空白、大小写和 Unicode，保留用户输入的展示形式。
- 标题不允许使用会破坏双链语法的换行、`[`、`]` 和 `|`。
- 正文保留可读的标题引用，解析后的关系保存目标笔记 UUID。
- 链接关系是可重建索引，正文是内容来源；关系中保存来源、目标、引用片段及解析版本。
- 代码块和行内代码中的 `[[...]]` 不作为笔记链接。
- 保存正文时重新解析该笔记的出链，并在同一个数据库事务中更新正文与关联索引。
- 重命名笔记时，通过解析器定位已确认的引用，更新相关正文和索引，禁止简单全局字符串替换。
- 目标不存在时保留未解析链接；创建目标笔记后重新解析相关引用。
- 反向链接显示来源笔记和上下文，点击直接打开来源笔记。
- 相互引用和自引用可以保存；关系图遍历需要去重，避免循环展开。
- 删除目标笔记后，来源正文保留原引用，界面显示目标已删除；恢复后重新连接。
- 回收站内标题暂时保留占用，避免同名新笔记让旧引用误指向其他内容。

### 8.3 自动保存

- 停止输入约 500～1,000 毫秒后自动保存，避免每个字符都触发数据库写入。
- 返回、切换笔记或离开编辑页时立即提交尚未保存的内容。
- 为同一笔记串行提交保存任务，并使用修订号避免旧请求覆盖新正文。
- 保存成功后显示“已保存”；写入失败则保留编辑内容并显示可重试提示。
- 应用进入后台时尽力提交，但不能把系统强制终止前的回调作为可靠保证。
- 验收要求为已确认保存的内容在重启后仍存在；尚未写入数据库的输入可能在突然终止时丢失。

### 8.4 与业务内容关联

P1 提供“关联账单 / 账本 / 存钱计划”选择器，保存实体类型和稳定 ID。

例如《旅行复盘》关联“旅行账本”与一笔交通支出，笔记内显示简要卡片，点击跳转详情；账单详情也显示关联笔记入口。

业务对象改名不影响关联；对象删除后显示失效提示，不自动创建新对象。首版不从笔记正文自动提取金额或自动记账。

### 8.5 笔记类型与处理状态

用户提到的“备忘录、日程规划、学习笔记”等，按**笔记类型**设计；另设独立的处理状态，方便区分内容用途与完成进度。

| 维度 | 首版内容 | 规则 |
| --- | --- | --- |
| 类型 | 普通笔记、备忘录、日程规划、学习笔记 | 一篇笔记选择一个主类型，可另加多个标签 |
| 处理状态 | 草稿、进行中、已完成、已归档 | 默认草稿；用户手动切换，日程到期不自动完成笔记 |
| 日程状态 | 待开始、进行中、已完成、已取消 | 每条日程独立管理，不与整篇笔记状态共用字段 |

- 笔记列表提供类型、处理状态的组合筛选，并在卡片上显示类型和状态标识。
- 新建时可选择类型模板：备忘录提供待办清单，日程规划提供“添加日程”入口，学习笔记提供目标、内容、总结等 Markdown 小节。
- 模板只是初始化内容，用户可自由编辑，不限制正文格式。
- 修改笔记类型不删除正文、图片、双链或已有日程；所有类型的笔记都可额外添加日程。
- 把笔记标记完成，不自动完成其全部日程；完成某条日程也不自动完成整篇笔记。
- 归档笔记保留正文及日程历史，默认列表隐藏，可通过筛选查看和恢复；归档不会自动删除手机日历事件。
- P1 允许创建自定义笔记类型、改名和归档；已被使用的类型不直接删除，内置类型保留稳定标识。

### 8.6 笔记内个人日程

日程作为笔记的结构化附加内容，展示为卡片，与 Markdown 正文一起构成笔记详情。一篇笔记可以没有日程，也可以关联多条日程，不要求用户手写特殊 Markdown 才能创建。

**日程字段：**标题、所属笔记、是否全天、开始与结束、时区、可选地点、简短说明、提前提醒分钟数、处理状态。

- 定时日程必须同时有开始和结束时间，结束晚于开始，允许跨日。
- 全天日程保存开始日期、结束日期；界面按包含结束日展示，写入系统日历时按接口要求转换结束边界，避免多一天或少一天。
- 定时日程保存 UTC 时刻和原始 IANA 时区；全天日程保存自然日，不按 UTC 零点转换日期。
- 切换设备时区后，定时日程按展示规则标注当地时间和必要的原时区信息，不改写原始时刻。
- 提醒建议提供“不提醒、提前 5/15/30 分钟、1 小时、1 天”；最终触发由目标日历应用及系统通知设置决定。
- 未加入手机日历的日程仍可在应用内查看和手动完成，但首版不另发应用通知。
- 列表按今天、即将到来、已完成查看，可筛选所属笔记及日程状态；取消的日程默认不进入待办列表。
- 已过去的未完成日程显示逾期提示，但不自动完成或写入手机日历。
- 标记日程完成仅改变应用内状态，手机日历中的普通事件没有统一的任务完成字段，不虚构完成状态同步。
- 删除笔记时，其应用内日程一并进入回收站；恢复时还原本地关联，外部日历处理按 8.7 执行。
- 修改正文中的日期文本不自动更改日程；日程编辑以结构化表单为准，避免正文与日历相互误改。

### 8.7 一键加入手机日历

**首版目标：主动单向写入，并支持手动更新已创建事件。** 应用中的日程是源数据，不扫描导入用户的全部系统日历，也不做后台双向同步。

#### 首次设置与常规使用

- 使用 `expo-calendar` 对接 Android 系统日历；所需原生配置和 API 以选定 Expo SDK 验证结果为准。
- 仅在用户首次点击“加入手机日历”时申请对应读写权限，不在启动应用时强制索取。
- 获取可写日历，让用户选择默认目标；排除只读日历，并显示日历所属账户或本地来源。
- 若设备支持，优先推荐或提供创建应用专用本地日历的入口；本地日历是否可创建需在不同设备验证，不能承诺所有厂商都支持。
- 授权及目标选择完成后，后续添加只需点击一次；写入期间锁定按钮，避免连续点击重复创建。
- 默认目标失效、变成只读或权限撤销时，要求重新选择或授权，不能静默改用其他账户日历。

#### 写入字段与隐私

| 手机日历字段 | 数据来源 |
| --- | --- |
| 事件标题 | 日程标题 |
| 开始、结束、全天、时区 | 日程结构化时间字段 |
| 地点 | 用户填写的地点 |
| 说明 | 日程简短说明、来源笔记标题，以及可用时的返回笔记链接 |
| 提醒 | 用户选择的提前提醒时间，按目标日历实际能力写入 |

- 不默认导出整篇 Markdown 正文、图片或账目内容；写入前在日程卡片中能看清将导出的信息。
- 返回笔记链接使用应用的稳定 URI scheme，包含笔记 UUID 和日程 UUID，也作为核查同一来源事件的稳定标记；链接无法打开时不影响事件本身查看。
- 应用内数据仍保存在手机本地。若用户选择带云同步的账户日历，导出的事件可能由该日历服务同步；选择时明确说明，避免把系统日历导出误称为始终仅在本机保存。

#### 防重复、修改与失败恢复

- 建立“本地日程 ID—当前安装实例—目标日历 ID—系统事件 ID”的映射，记录上次写入的日程修订号与摘要。
- 同一日程已经成功添加且无修改时，按钮进入“查看日历事件”，重复点击不新建；需要更新时使用既有事件 ID。
- 日程修改后标记“手机日历待更新”，由用户点击更新；不在后台自动覆盖系统事件。
- 更新前比较已写入字段的摘要，若检测到用户在手机日历中修改事件，先展示差异并让用户选择是否覆盖；不反向改写本地日程。
- 系统事件被手动删除时显示“事件不存在”，由用户明确选择重新添加；目标日历被移除时重新选择目标。
- SQLite 与系统日历不在同一个事务内：记录待写入操作及稳定标记，执行后再保存返回 ID。若中途终止导致结果不明，先核查已知事件或稳定标记，再决定是否重试；不能盲目新增。
- 只有系统接口确认成功后才显示“已加入”；权限拒绝、取消、无可写日历、原生接口错误都显示明确结果，并保留本地日程。
- 无法直接写入而转用系统事件编辑页时，明确显示“请在日历中确认保存”；未取得成功结果前不标记为已添加。
- 系统接口或提醒能力的厂商差异必须在 Development Build 和签名 APK 真机测试，不仅在 Expo Go 测试。

#### 删除、归档与恢复边界

- 默认删除或归档笔记、取消或删除日程，只处理应用内数据，并提示已加入的手机日历事件仍存在。
- 如用户明确选择“同时删除已加入的日历事件”，仅按已记录的事件 ID 操作本应用创建的关联事件，不批量清理其他日历内容。
- 外部事件删除失败时记录待处理状态，不显示外部删除成功；保留映射以便用户重试。
- 应用备份包含本地日程，但系统事件和可用权限由手机系统管理；恢复后把旧日历映射标为待核查，不自动重放添加操作。
- 系统事件 ID 不保证跨手机、重装后或日历账户变化后仍然有效；必须核查事件来源与稳定标记，不能仅凭相同 ID 覆盖或删除事件。
- 默认日历偏好也需要恢复后重新验证。本功能不依赖应用持续后台运行；事件写入后由手机日历负责提醒。

### 8.8 Markdown 手动插图与图片管理

手动插图是 P0 必备功能，具体要求如下：

1. **插入入口**：编辑器工具栏提供“图片”，可选相册、系统文件选择器或拍照；只在确实需要时请求对应权限。
2. **位置与语法**：在当前光标或选区位置插入标准 Markdown 图片语法，图片说明可编辑；用户也可手动修改 Markdown。
3. **持久化**：获取所选图片后，校验实际格式与大小，再复制到本地附件目录；成功后才写入正文，不能把相册或缓存的临时 URI 当成长期地址。
4. **文件标识**：文件名使用 UUID，扩展名与实际图片格式一致；不依赖原文件名，避免重名覆盖和路径失效。
5. **本地相对路径**：例如 `![学习资料](attachments/6c1f-example.jpg)`；渲染时通过附件记录定位文件，不暴露设备绝对路径。
6. **图片体验**：支持预览、大图查看、替换、删除引用和说明编辑；长图保持比例，列表使用缩略图，正文不直接解码所有原图。
7. **格式与容量**：首版保证 JPEG、PNG、WebP 静态图；HEIC 等来源格式如需支持，先验证转换为兼容格式。建议单张上限 20 MB，并提供明确错误提示；压缩可作为用户可选操作。
8. **权限与取消**：选择取消、拒绝相机权限、图片复制失败或空间不足时不插入无效占位，不清空正文。优先使用系统照片选择器，避免申请无关的全盘存储权限。
9. **引用生命周期**：解析正文中的有效图片引用，维护附件关联；删除一个引用不立刻删除文件，仍被其他笔记或回收站引用的文件继续保留。
10. **异常与清理**：图片复制后正文保存失败，可保留待重试文件；未引用附件在有宽限期的清理任务中处理，不能删除尚未完成保存的图片。
11. **手动路径与外链**：手动输入不存在的本地路径时显示缺图提示；远程图片不默认联网加载，可由用户显式选择加载或下载为本地附件，下载失败不影响其他内容。
12. **导出与恢复**：P1 导出含图笔记时，使用包含 `.md` 与 `attachments/` 的文件包；完整备份始终包含引用图片。需要保留类型、状态、日程信息时使用文档化的 front matter 或附属 JSON，不把这些结构化信息混入不可编辑的正文。

图片说明与正文参与搜索；首版不承诺对图片内容做 OCR 检索，也不承诺动图和任意文件附件支持。

## 九、技术架构

### 9.1 推荐技术选型

| 层级 | 推荐方案 | 用途与说明 |
| --- | --- | --- |
| 应用框架 | Expo + React Native + TypeScript | 面向 Android 开发，保留后续 iOS 扩展可能 |
| 路由 | Expo Router | 底部导航、详情页、表单页、模态页 |
| 主数据库 | expo-sqlite | 保存笔记、账目、关系、计划及持久化设置 |
| 文件管理 | expo-file-system | 图片、临时文件、导出与备份文件 |
| 文件导入导出 | expo-document-picker、expo-sharing | 系统选文件、分享或另存备份 |
| 图片输入 | expo-image-picker，按需配合 expo-image-manipulator | 相册、拍照、图片格式转换和可选压缩 |
| 手机日历 | expo-calendar | 日历权限、可写目标选择、事件创建、查询与手动更新 |
| 界面状态 | Zustand 或轻量 Context | 当前账本、筛选、主题和编辑器临时状态 |
| 表单校验 | React Hook Form + Zod，或等价轻量方案 | 输入校验及错误展示 |
| Markdown | 可控解析器 + React Native 渲染组件 | 普通 Markdown、双链扩展、代码区排除 |
| 图表 | 基于 react-native-svg 的兼容方案 | 折线图、环形图、局部关系图 |
| 日期 | date-fns 或少量封装工具，补充明确的时区处理方案 | 账目自然日、日程 UTC 时刻、IANA 时区与全天边界 |
| 标识符 | Expo 支持的 UUID 生成方案 | 稳定实体 ID，避免以标题作为主键 |
| 测试 | Jest / jest-expo + React Native Testing Library | 业务规则和关键交互验证 |
| Android 验证 | 真机 + 模拟器，按需使用 Maestro | 安装、离线使用、跨页流程和升级恢复 |
| 构建 | EAS Build 或配置好的本地 Android 构建 | 输出签名 APK |

开始开发时选用**当时的稳定 Expo SDK**，依照该 SDK 的兼容矩阵固定依赖版本，并使用 `expo install` 安装 Expo 管理的原生依赖。规划阶段不绑定未经验证的版本号。

图表、Markdown、日历与图片输入、备份归档库先做技术验证，再确定具体包。尤其验证目标设备的本地日历来源、全天边界、权限拒绝和提醒行为。原生能力以 Development Build 和最终 APK 为准，不能只以 Expo Go 中运行成功作为验收依据。

### 9.2 分层原则

```text
页面与组件
    ↓
业务服务：记账 / 计划 / 存钱 / 笔记链接 / 日程 / 备份恢复
    ↓
数据访问层：参数化查询 / 事务 / 分页 / 聚合
    ↓
SQLite + 应用私有文件目录
```

日历接入作为独立的系统适配层，由日程业务服务调用，不能把系统事件 ID 当作本地日程主键。日历写入使用可恢复的操作记录，处理跨本地数据库与系统接口的部分成功。

- 页面负责展示与用户输入，不直接拼接 SQL。
- 所有写入先通过业务服务校验，再进入数据库事务。
- 金额规则、存钱分配、计划确认和恢复逻辑集中管理，避免多个页面各算一遍。
- 数据库是业务事实来源；界面状态只保存短期 UI 数据。
- 不把主业务数据保存在 AsyncStorage、浏览器 localStorage 或大块 JSON 设置文件中。

## 十、数据模型与约束

### 10.2 关系设计

```text
账本 1 ── N 分类
账本 1 ── N 实际账目
账本 1 ── N 计划账目
分类 1 ── N 实际账目 / 计划账目
计划账目 0..1 ── 0..1 实际账目
账本 1 ── N 存钱计划
存钱计划 1 ── N 存钱记录
实际账目 0..1 ── N 存钱记录
笔记 N ── N 笔记：通过 note_links
笔记类型 1 ── N 笔记
笔记 1 ── N 日程
日程 1 ── N 设备日历关联：当前安装实例仅保留一个有效目标
笔记 N ── N 标签：通过 note_tags
笔记 N ── N 图片：通过 note_attachments
```

### 10.3 必要约束与索引

- 开启 SQLite 外键约束，所有 SQL 使用参数绑定。
- 用复合外键或等价约束保证账目、计划的 `ledger_id`、`category_id`、`direction` 一致。
- 金额设置大于 0 的 CHECK 约束，收支方向和计划状态设置枚举约束。
- 分类名称按账本与方向建立规范化唯一约束；笔记标题按规范化结果全库唯一。
- 计划关联实际账目设置唯一约束，防止同一实际账目完成多个计划。
- 有效的账单与存钱计划分配设置组合唯一约束；软删除后的恢复要处理冲突。
- 跨行规则，如分配总额和存钱非负余额，由业务层在事务内重新读取并校验。
- 账目按 `(ledger_id, occurred_on, id)`、`(ledger_id, category_id, occurred_on)` 建索引。
- 计划按 `(ledger_id, status, expected_on)` 建索引。
- 存钱记录按 `(plan_id, occurred_on)` 和 `transaction_id` 建索引。
- 笔记按更新时间、文件夹建索引，双链按来源和目标分别建索引。
- 笔记增加 `(type_id, status, updated_at)` 索引；笔记与日程状态使用独立枚举约束。
- 日程按 `note_id`、状态与开始时间建索引；定时和全天字段分别校验完整性、互斥性及结束边界。
- 日历关联按 `(schedule_id, installation_id)` 对有效目标设唯一约束，已知系统事件 ID 也做适用的唯一约束；不使用可跨设备误认的裸事件 ID 作为唯一身份。
- 日历导出状态至少区分待写入、已添加、待更新、失败、结果待核查；本地修订号变化不能继续显示完全一致。
- 账单明细和笔记列表采用稳定排序与分页，避免日期相同引发重复或漏项。

### 10.4 中文全文搜索

FTS5 是否可用需要在选定 Expo 构建配置中验证。即使可用，默认分词也不必然满足中文任意词片段搜索。

首版先定义并验收中文搜索行为：标题和正文可按连续文字片段搜索。在目标数据量下验证参数化子串查询的耗时；若不足，再评估 FTS5 trigram 或独立中文索引。搜索能力不能只以英文样例验收。

## 十一、本地存储、备份和隐私

### 11.1 数据保存方式

- 数据库存放于应用私有目录。
- 笔记正文、账目、计划和关系保存在 SQLite。
- 笔记类型、处理状态、附加日程与日历关联操作记录也保存在 SQLite；系统日历事件由 Android 日历提供方管理。
- 图片复制到持久化附件目录；不要依赖临时文件路径或相册外部 URI 长期有效。
- SQLite 写入使用事务，启用适当的日志模式；设置迁移前备份和失败回退策略。
- 存储空间不足、图片复制失败、数据库写入失败时，明确告知失败，不显示保存成功。

### 11.2 完整备份格式

建议提供一个带自定义扩展名的 ZIP 备份包，例如 `charge-backup-20261101.zip`，包含：

```text
manifest.json      格式版本、schema 版本、应用版本、导出时间、文件摘要
database.sqlite    一致性数据库快照
attachments/       快照引用的图片文件
```

- 导出期间协调写入，使用 SQLite 支持的一致性备份或快照接口；不能直接只复制正在使用的主数据库文件而忽略 WAL。
- 数据库快照与附件清单必须匹配，导出期间防止附件被垃圾回收。
- 包内仅使用相对路径，不携带手机私有目录的绝对路径。
- 首版完整备份采用覆盖恢复，暂不做复杂的跨设备数据合并。
- 图片缺失、包损坏、摘要不匹配、格式不支持时，给出清晰报告，不替换现有数据。
- 备份包含笔记类型、状态及所有本地日程，不以备份包恢复系统权限或重建手机日历事件；日历映射恢复后统一进入待核查状态。
- 解包前检查文件路径与大小上限，阻止目录穿越和异常膨胀的归档文件。
- 导入更高版本且无法识别的数据时拒绝恢复，提示升级应用。

### 11.3 恢复流程

1. 用户通过系统文件选择器选取备份。
2. 在临时目录解包，校验格式、文件完整性、数据库结构和外键关系。
3. 展示备份日期、笔记数、账目数、账本数，并说明将覆盖当前数据。
4. 替换前自动保存一份当前数据的可恢复快照。
5. 暂停写入并关闭数据库，在受控流程中切换数据库和附件目录。
6. 使用恢复日志记录切换阶段，使中途退出后能够回退或完成切换。
7. 重新打开数据库，执行适用迁移及索引校验，检查成功后刷新应用。
8. 任一步失败都保留原数据或自动回退，不留下数据库和附件版本不一致的半成品。

覆盖恢复需要用户确认，这是防止当前数据被替换的必要交互。

### 11.4 回收站与彻底删除

- 笔记、实际账目和独立存钱记录支持软删除与恢复；计划删除也需处理实际账目关联。
- 笔记回收站同时保留其附加日程和图片引用；恢复本地数据不会自动再次向手机日历添加事件。
- 首版不自动清空回收站，避免仅因时间经过而永久丢失资料。
- 彻底删除必须显示关联影响。涉及计划状态、存钱余额的操作，仍要经过一致性校验。
- 笔记附件只有在确认没有有效或可恢复引用时，才能进行垃圾回收。
- 归档账本和分类不等同于删除，历史数据保持可查。

### 11.5 隐私边界

- 不建设业务服务器，不默认启用会上传笔记或账目内容的分析、日志和崩溃收集服务。
- 发布版避免把正文、备注、金额明细和备份内容写入日志。
- 配置 Android 系统备份规则，默认排除业务数据库和附件，确保不会通过系统自动备份进入云端；在目标 Android 版本验证规则。
- 用户主动选择把备份分享到网盘属于用户控制的导出行为，界面说明备份包含个人资料。
- 用户主动“加入手机日历”是受控的系统导出，仅写入日程字段；若选择云账户日历，事件可能由其服务同步，默认优先推荐设备本地日历，不强制绑定云账户。
- 图片按需通过系统选择器或相机获取，不默认读取整个相册、不自动上传；首版远程图片不默认联网加载。
- 日历与相机权限按功能使用时申请，拒绝权限不会影响记账、纯文本笔记和本地日程保存。
- 默认数据库和备份未加密，不把应用私有目录描述成数据库加密。
- 应用卸载或清除数据可能丢失本地资料，因此设置页提供明显的备份入口和最近备份时间。
- 如后续增加应用锁，它只是访问控制；数据库加密和加密备份需要单独设计密钥管理与恢复方式。

| 分类一致性 | 不允许收入账目选择支出分类，不允许引用其他账本分类 |
| 计划确认 | 连续点击只产生一条实际账目；未执行和已取消计划不进入实际统计 |
| 日期口径 | 月初、月底、闰日、跨年与设备时区变化后，已选自然日不漂移 |
| 统计联动 | 修改、删除、恢复账目后，明细汇总与图表同步变化 |
| 存钱独立操作 | 增加或减少只改变计划进度，不增加月收入或月支出 |
| 多计划分配 | 总分配不能超过账单金额；关联删除、恢复、改金额时保持一致 |
| 存钱非负 | 减少、删除增加记录、恢复历史减少记录均不能导致当前金额为负 |
| 双向链接 | 已存在、未创建、重命名、删除、恢复和自引用场景结果正确 |
| Markdown 解析 | 代码区域中的双链不计入关联，别名显示和跳转正确 |
| 中文搜索 | 中文标题和正文片段可查到，空查询和特殊字符不会报错 |
| 编辑保存 | 已显示保存成功的笔记，重启后内容完整；保存失败有提示且不丢编辑内容 |
| 笔记类型与状态 | 备忘录、日程规划、学习笔记可创建和筛选；切换类型保留正文、图片、双链与日程；类型和完成状态互不混用 |
| 多日程 | 任意笔记可添加多条日程，分别设置状态；日程完成与笔记完成不自动相互覆盖 |
| 定时与全天 | 同日、跨日、全天多日、设备时区变化后显示正确；写入手机日历无日期偏移或多一天、少一天 |
| 首次加入日历 | 第一次点击才请求权限并选择可写目标；授权成功后可添加，拒绝或取消时本地笔记和日程不丢失 |
| 后续一键添加 | 默认目标有效时，单击即可写入完整日程；不要求用户再次手填标题或时间 |
| 日历防重复 | 连点、返回重进、进程中断后核查不会盲目重复添加；结果不明时显示待核查，不假报成功 |
| 日历编辑与删除 | 本地修改显示待更新；外部修改有差异提示；外部事件已删除或目标失效时提示重新处理 |
| 日历隐私与失败 | 本地日历与云账户来源可辨认；无可写目标、权限撤销、接口错误时可继续使用本地功能，不静默改写其他日历 |
| 日历恢复边界 | 备份恢复后旧映射待核查，不自动重建事件，也不误修改相同 ID 的无关事件 |
| 手动插图 | 相册、文件、拍照可在光标处生成图片语法；取消与权限拒绝不破坏正文，复制失败不插入失效引用 |
| 图片持久化 | 删除源相册图片、结束进程、重启手机后，本地已导入图片仍正常显示；大图可查看、可替换、可移除引用 |
| 图片导出与清理 | 含图 Markdown 文件包离线可读；删除一处引用不误删其他引用或回收站图片 |
| 完整备份 | 导出后在干净安装中恢复，笔记、类型、状态、日程、账本、图片、关联和汇总均一致 |
| 损坏备份 | 校验失败、空间不足和导入中断后，原数据仍可使用 |
| 离线使用 | 飞行模式下可记账、写含图笔记、管理日程、看图表、操作存钱计划和本地导入导出；存在可写本地日历时可离线添加事件 |
| 版本升级 | 已安装旧版本的数据可随签名升级迁移，不清空数据库 |

### 13.2 测试重点

- **单元测试**：金额解析与汇总、日期区间、双链及图片引用解析、存钱分配规则、日程时区与全天结束边界。
- **数据库集成测试**：计划确认原子性、同一操作重复提交、软删除与恢复冲突、笔记类型与状态迁移、图片引用、外键和迁移。
- **日历集成测试**：用模拟适配层验证成功、失败及结果不明后的状态，再在真机验证权限、系统事件 ID、提醒与外部修改冲突。
- **备份集成测试**：快照一致性、附件缺失、包损坏、旧版本迁移、恢复中断回退、日程还原与日历映射失效处理。
- **真机流程测试**：首次安装 → 创建账本 → 分类 → 计划 → 实际记账 → 存钱分配 → 关联笔记 → 手动插图 → 添加日程 → 加入手机日历 → 导出恢复。
- **异常场景**：快速连续操作、切后台、强制结束进程、存储不足、图片选择取消、相机与日历权限拒绝或撤销、只读日历、无日历提供方、键盘遮挡、超长备注。
- **图表验证**：使用可手算的数据集比较明细、SQL 汇总和图表数值，不能仅凭图形看起来正常。

测试投入集中在数据正确性和用户核心流程，不追求没有实际价值的全量快照或纯界面覆盖率。

### 13.3 性能与兼容目标

开发初期选定一台中端 Android 真机作为基准，并记录型号、系统版本和构建方式。以下作为发布优化目标，需实测确认：

- 初始性能数据集：10 个账本、50,000 条实际账目、3,000 篇笔记，每篇平均约 3 KB 正文。
- 普通明细首屏与月份切换目标 500 毫秒内完成数据加载和主要展示。
- 月度统计目标 1 秒内展示。
- 中文搜索目标 1 秒内给出首批结果；搜索输入采用防抖。
- 长列表滑动保持流畅，图片使用缩略图和适当尺寸，不批量解码全部原图。
- 局部关系图首屏限制节点数，例如最多 100 个，超出时提示缩小范围。
- 冷启动目标约 3 秒内可操作，发布构建实测；大量历史迁移单独显示进度。
- 最低 Android 版本依据选定 Expo SDK 与原生依赖确定，并在需求定稿时写入兼容清单。
- 日历至少覆盖原生 Android 或接近原生的设备，以及一个常用厂商系统；记录可写本地日历、权限、全天事件和提醒的实际支持情况，不承诺所有厂商提醒均在同一时刻精确触发。

## 十四、Android APK 打包与发布

1. 确定应用名称、包名、图标、启动页、版本号和 Android `versionCode`。
2. 开发阶段使用 Development Build，验证 SQLite、文件操作、图片选择与相机、系统日历和图表的原生兼容性；配置日历及相机等实际需要的权限。
3. 为直接安装配置 Android APK 构建产物；使用 EAS 时，在对应构建 profile 中明确配置 `android.buildType: "apk"`。
4. 构建签名 APK，按兼容清单在真机进行全流程离线验收，特别验证一键加入手机日历和手动插图。
5. 验证同签名、较高版本号的升级安装保留数据，不把卸载重装当成升级测试。
6. 保存签名密钥、别名、恢复信息及构建说明；密钥丢失会影响后续覆盖升级。
7. 完成交付版本的备份恢复演练后再发布。

可以使用 EAS 云构建或配置好的本地 Android 环境。云构建涉及源码和构建配置上传，应作为构建方式单独选择；手机上的笔记和账务数据库不应被放入源码或构建上下文。

业务数据本地保存与使用云构建是不同问题。发布版首版无需远程业务接口，也不依赖在线更新才能正常运行。未来如需上架商店，可另行增加 AAB 和商店合规准备。

## 十五、主要风险与应对

| 风险 | 可能影响 | 应对方式 |
| --- | --- | --- |
| “计划”和“实际”混在同一统计中 | 支出被重复计入 | 数据模型分离，统计入口只查询实际账目 |
| 存钱与支出重复计算 | 收支和目标进度失真 | 存钱记录单独保存，账单关联只形成分配 |
| 多模块编辑、删除、恢复未同步 | 计划状态和存钱金额错误 | 跨模块业务服务 + 事务 + 关联约束 + 集成测试 |
| 以笔记标题作为唯一关系标识 | 重命名导致链接失效 | UUID 作为实体 ID，解析器维护正文引用和关系索引 |
| 中文检索方案不适配 | 搜索不到连续中文片段 | 中文样例先验收，再选 FTS 或子串方案 |
| 自动保存竞态 | 旧正文覆盖新内容 | 串行保存、修订号、写入确认 |
| 笔记类型、笔记状态与日程状态混用 | 切换用途后误删内容或误标记完成 | 独立字段，切换类型不清空内容，各级状态手动管理 |
| 系统日历与数据库部分成功 | 重复事件、界面假报成功 | 稳定操作标记、保存映射、结果核查，未知结果不盲目重试 |
| 厂商日历能力与权限差异 | 无可写目标、提醒失败、全天日期偏移 | 提前真机验证，明确失败原因与降级状态，保持本地日程可用 |
| 选择带云同步的账户日历 | 与用户本地保存预期不一致 | 展示日历来源，优先本地目标，明确主动导出的同步边界 |
| 插图使用临时路径或清理错误 | 重启、源文件删除或恢复后缺图 | 私有目录副本、相对路径、引用索引、含图备份及安全清理 |
| 恢复包部分替换或附件缺失 | 数据库和图片不匹配 | 临时校验、恢复日志、旧快照和故障回退 |
| 用户卸载、设备损坏 | 本地资料丢失 | 完整备份入口、最近备份信息、恢复演练 |
| 数据或图片持续增长 | 页面卡顿、备份耗时 | 分页、索引、聚合查询、缩略图、附件引用管理 |
| 追求完整 Obsidian 兼容 | 首版延期 | 固定双链、反链、Markdown 范围，其余放后续版本 |

## 十六、最终交付内容

1. Expo + TypeScript 完整源代码、依赖锁文件和环境启动说明。
2. 可安装、已签名的 Android APK，以及应用版本与构建说明。
3. 需求定稿、页面结构、数据库模型和版本迁移说明，包含笔记类型、状态、附加日程与日历操作规则。
4. 本地完整备份格式说明，以及经验证的导出、恢复、Markdown 插图与手机日历使用指南，说明日历账户同步和权限边界。
5. 核心业务测试、真机验收结果、兼容设备信息和已知限制。
6. 一份不含真实个人资料的演示数据，用于回归与功能展示。
7. Android 签名材料的保存与移交说明。

## 十七、立项时需要定稿的产品选择

本规划已给出默认建议，可以以此进入原型阶段。以下项目需要在正式编码前定稿，以免影响模型和交互：

| 选择项 | 本规划建议 |
| --- | --- |
| “计划账目”的含义 | 提前登记未来收支，由用户手动确认发生 |
| 存钱增加、减少与账单的关系 | 支持独立手动记录，也支持按账单部分金额显式分配 |
| 分类是否全局共享 | 各账本独立，提供复制模板 |
| 关联笔记体验的首版范围 | Markdown、双链、反向链接、中文搜索；局部图谱放 P1 |
| 笔记的类型与状态 | 备忘录、日程规划、学习笔记等作为类型；另设草稿、进行中、已完成、已归档 |
| 笔记日程 | 所有类型均可附加多条日程，支持定时、全天、地点、提醒与独立状态 |
| 手机日历接入 | P0；首次授权选可写日历，后续一键添加，修改后手动更新，不做双向同步 |
| 手机日历目标与隐私 | 优先设备本地日历；账户日历可能云同步，用户选择时明确展示 |
| Markdown 手动插图 | P0；相册、文件、拍照输入，本地持久化、相对路径、含图备份；P1 提供含图 Markdown 导出 |
| 首版是否需要资金账户余额 | 不需要；只做收支与目标追踪，月结余不等于资产余额 |
| 是否提供多币种和周期计划 | 后续版本处理 |
| 是否支持笔记文件直接同步 | 不支持；数据库为主，提供 Markdown 导出 |
| 首版安全级别 | 本地私有存储、无业务上传、完整备份；加密作为单独扩展 |
| 首个交付范围 | 阶段 6 后提供 P0 内测，阶段 7 后交付完整 V1.0 |

建议第一个开发任务为：完成核心页面原型、数据模型和 Android 技术验证；同时验证系统日历写入与图片持久化，确认记账、存钱和日程的业务规则后，再初始化正式工程。
