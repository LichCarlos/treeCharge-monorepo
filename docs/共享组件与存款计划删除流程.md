# 共享组件与存款计划删除流程

更新日期：2026-11-03。移动端 0.1.6 / versionCode 7。

## 共享组件与数据

- `RecordComposer` 是新建收支、明细编辑及存取记录的统一入口，复用 `CategoryPager` 和统一图标绑定。
- `CategoryAllowanceBar`、`BudgetEditor` 和月度共享快照负责上限、剩余额度及分配设置。
- `SavingsPlanCard` 共用于正常列表、计划详情和已删除列表，统一累计金额、目标、进度与状态。已删除卡片不可进入编辑或记账。
- `ModalPanel` 统一弹窗容器；`ActionMenu` 统一操作菜单；`ConfirmActionModal` 统一删除、恢复和永久删除的按钮、忙碌状态及错误反馈，支持管理员理由及重复点击保护。
- `useWorkspaceState` 与月度预算共用状态存储和失效机制，按用户、工作区、账本、月份区分。存款计划不使用日期筛选。
- 成功写入后刷新共享状态、列表和统计，并清除对应账号工作区的持久缓存；删除对象相关草稿及账本选择同时清理。切换账号清空旧账号业务缓存，主题设置独立保留。
- 顶部刷新与下拉刷新统一使工作区共享快照失效，再读取最新列表和预算，覆盖其他设备修改后的同步场景。

## App 已删除计划页面

抽屉树与面包屑路径为“账本管理 → 存款计划 → 已删除计划”；存款计划列表也提供入口。Web 不显示该页面、回收站或恢复入口。

卡片使用浅灰背景，显示名称、删除时间、删除前累计金额、目标、弱化进度及已删除状态。恢复使用主题色，永久删除使用危险色。空页面仅显示“暂无已删除计划”。删除前金额保存在删除批次快照中，不能因记录被隐藏而变成零。

## API 与删除边界

首次删除仍调用 `DELETE /v1/workspaces/:w/entities/:id`，将计划关联账本、类别、记录、备注和所属配置软删除，记录删除批次。恢复调用 `POST /v1/workspaces/:w/entities/:id/restore`，只恢复本批次涉及的实体，先前单独删除的记录保持删除。

新增 `DELETE /v1/workspaces/:w/savings-plans/:id/permanent`，必填 `operationId` 和 `expectedRevision`，管理员还需操作理由。仅支持已完整软删除的存款计划或其账本入口。非删除状态、过期版本及跨工作区请求均被拒绝；同一操作编号重试返回原结果。

迁移 `015_permanent_savings_deletion.sql` 提供受约束的数据库函数。硬删除从关联账本归属开始，包含此前单独软删除的子记录，清理流水、备注、类别、目标、计划账目、所属字段/标签/关系、预算配置、模板实例、删除批次和相关绑定。外部实体只解除关联，公共图标、其他账本、账号、会话均保留。

历史表继续对运行角色保持追加写入约束；仅受限制的数据库所有者函数在本次删除集合内清理所属历史。永久删除新增最小操作审计及幂等回执，不提供数据恢复。数据库备份属于运维备份，不作为 App 恢复入口。

完整清理与操作回执在一个数据库事务中完成。任一阶段失败会回滚，不留下部分删除；删除成功后重建同名计划使用新的 UUID。

## 验证

- 36 项自动化检查与工作区类型检查。
- PostgreSQL 13 独立临时数据库覆盖批次恢复、同名隔离、计划/账本入口永久删除、先前单独删除的子记录、跨账本字段和关系解绑、历史预算清理、权限、版本、重复请求及注入故障后的事务回滚。
- 实际 Expo Web App 验证恢复入口隐藏、同名创建、预算共享与历史月份隔离。
- 隔离组件页面验证删除卡片、确认与取消、失败保留、恢复、软删除返回及永久删除后列表刷新。
- Android 独立测试包使用模拟接口，不连接生产账号或写入用户业务数据；原生验收截图与正式包检查见发布记录。
