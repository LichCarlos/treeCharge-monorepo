## 一、默认行为与使用流程

**默认不勾选任何模板。** 不创建演示收入、支出或存款，不强制录入工资。用户可继续自建账本和分类，逐笔手动记录收支。

新建账本提供两个入口：

1. **空白账本**：默认选项，填写名称和账本类型，用户自行管理结构。
2. **从模板创建**：用户主动选择模板、填写必需参数、自行命名，查看将生成的账本/分类/标签/预算预览后点击创建，即可使用。

默认提供 5 个模板。模板为可编辑的起点，实例化后用户可以增删分类、辅助标签、分配项、字段，修改金额、百分比及关联关系，不被系统模板锁定。系统模板升级不自动覆盖已有账本。

模板只创建结构、配置、预算或计划。所有实际收入、支出、存入、取出仍由用户手动确认，不因选择工资或生成预算而视作实际发生。

| 月度信封预算 | 支出账本；可关联存钱账本 | 名称、可分配金额、月份 | 住房、饮食、交通、日用账单、弹性消费的固定额度，结余储蓄为剩余 |

比例分配、信封预算、52周挑战与应急金属于常见个人预算方法。本次以这些通用方法设计模板，不复制商业产品界面或宣称提供了特定产品的最新功能对比。示例金额和比例是可修改的初始化参数，不是对用户资产的推断。

### 2.1 我的工资分配

用户提供的表格只参考分类结构和“金额｜占比”的展示形式，**不把参考金额、工资档位、比例或汇总写成用户数据，也不校正参考表作为业务任务。** 模板预备14项消费tag：日常饮食、通勤交通、社交娱乐购物、随心花、话费、洗护日用品、医护、水电物业、保险、住房房租、换季衣服鞋子、电子消费、短途出行旅行、人情支出；另提供长期储蓄预算tag。

- 创建时仅带入分类名称和可编辑结构，金额初始为空；用户可先建账本，再补充工资与各tag分配。没有明确额度前显示“待设置”，不假设参考值或假报超支。
- 一个预算期只有一个可支配工资总池，分类预算由这个总池分配。任意正数工资均可输入，不限制参考档位，不插值套用参考表。
- 月工资按税后、用户实际可自由分配的金额输入，系统不自动计算个税或社保。
- 选择已有工资实际收入作为分配基数是可选操作，只引用这笔金额，不复制生成第二笔收入。
- 用户选“金额”时派生占工资比例，选“比例”时按用户工资派生金额，不用参考表的展示百分比倒推。
- 长期储蓄作为预算去向，具有稳定预算项 ID，可以关联现有存钱账本，或由用户选择新建并命名存钱账本；不作为消费支出分类参与消费饼图。
- 暂不关联实际存钱账本也可完成预算创建，后续再选择；预算中显示“未关联存钱账本”。
- 新建存钱账本需明确目标金额，不能擅自把本月预计结余当作长期目标。
- 用户可新增“教育”“家庭支持”“长期储蓄二”等分配项，设为固定金额、工资百分比或剩余分配，并选择用途与去向。

用户修改工资或分配规则后，先预览新额度和已有消费的影响，显式保存新预算修订。已有调剂记录和消费仍保留，不能重新套模板覆盖实际使用情况。每期未分配金额单列；只有配置了剩余分配规则并完成用户确认，才转为长期储蓄等目标的计划额度。

### 2.2 50/30/20 比例分配

示例基数 10,000 元：必要生活 5,000 元，弹性生活 3,000 元，长期储蓄 2,000 元。必要生活内可有住房、饮食、交通、基础账单，弹性生活可有娱乐、购物、旅行。

默认先按父级预算约束，子分类不重复再分一遍全部工资。需要对子分类分配时，明确选择以父级预算为基数，其子项总额不得超过父级额度；未分配部分显示“本级未分配”。

储蓄使用剩余项确保到分闭合；用户也可修改比例。模板名称是初始化方法，用户改规则后显示当前实际比例，不能仍强称符合 50/30/20。

### 2.3 月度信封预算

示例月度基数 10,000 元：住房 3,000、饮食 1,500、交通 500、日用账单 500、弹性消费 1,000，结余储蓄 3,500。所有额度可编辑，不从工资档自动套入。

每个信封对应一个主分类预算。实际消费仍逐笔记入所属分类，展示预算、实际、剩余额度和超支。第一期不自动把未用额度滚入下月；复制下一月只复制预算规则，用户决定是否调整。

### 2.4 52周递增存钱

第 n 周计划金额=首周金额+(n−1)×递增金额。首周 10 元、递增 10 元，52 周合计 13,780 元。

- 用户填写开始日期后，每周按自然日递增 7 天安排，不自动对齐其他周一而改变用户日期。
- 每周生成手动存入计划，归属“挑战存入”主分类；另建“临时取出”主分类及“52周挑战”辅助标签。
- 点击确认并可改实际金额后才生成实际存入；跳过、逾期或取消不计实际余额。
- 改周数或规则时只重新生成尚未执行计划，已完成记录保持原值，并展示目标调整预览。
- 目标值是计划总额；实际进度来自真实手动存入减取出。

### 2.5 应急备用金

示例每月必要支出 5,000 元、覆盖 6 个月，则目标 30,000 元；计划月存 2,000 元、暂无实际存款时，预计需 15 个月。

- 初始覆盖月数可选 3 或 6，自定义范围由有效性校验控制；示例不声称适合每个人。
- 已有存款必须通过手动期初存入记录进入实际余额，不能只把计算表的参数直接写成真实资产。
- 预计月数=向上取整(max(目标−实际当前金额,0)/计划月存额)。月存额为 0 时显示无法估算，不除零。
- 未执行计划不改变进度；不计算利息和收益，不自动投资或转账。

## 三、预算派生规则

本功能扩展一期固定业务规则，但不开放脚本或自由公式执行。

| 规则 | 参数 | 结果 |
| --- | --- | --- |
| 固定金额 | 整数分 | 直接作为预算 |
| 百分比分配 | 基数引用、比例基点（0～10,000） | 基数×比例，四舍五入到分 |
| 剩余分配 | 同一预算组中的剩余分配权重 | 扣除其他分配后的余额，按权重分配 |
| 系统目标计算 | 周数/首额/递增或必要支出/月数 | 仅使用验证过的内置计算器 |

- 同一预算组的所有百分比基于明确的同一基数，不能让后加入的比例无提示按剩余金额计算。
- 基数也可显式为父预算项，但引用只能指向祖先，不能形成预算循环依赖。
- 初次分配额度不能超出基数，超分显示差额，可保留草稿。此规则仅约束分配方案，**不阻止用户保存已真实发生的超支消费**。
- 没有剩余项时，未分配部分单列，不强制偷偷分给某分类。
- 多个剩余项按正整数权重分配；最小货币单位用最大余数法补齐，平局按稳定排序，不丢一分钱。
- 分配项金额可为 0，表示预算额度为 0；实际入账明细金额仍必须大于 0。
- 有效工资预算的工资必须大于0；为空或0时保留待设置状态，不假算占比。真实消费超出额度时余额允许为负，不能为使预算好看而截断消费。
- 各占比以金额/工资派生，保留两位小数用于显示，展示之和可能有 0.01% 级差异；金额和总计始终精确闭合。
- “预计净长期储蓄”与“实际已存入”分开显示；月底实际结余、月预算结余和存钱余额不是同一个数字。

## 四、模板实例、树与标签关系

工资模板实例示意：

```text
用户命名的工资支出账本
├─ 工资收入〔收入主标签〕
├─ 日常饮食〔支出主标签〕 → 用户手动消费明细
├─ 通勤交通〔支出主标签〕 → 用户手动消费明细
└─ 其他12项支出主标签 → 用户手动消费明细

本月预算方案〔配置实体，通过引用关联账本〕
├─ 14个消费预算项 → 分别引用对应分类UUID
└─ 净长期储蓄预算项 → 可选引用用户命名的存钱账本UUID
```

预算项不伪装成一笔真实明细，预算方案也不改变主树唯一归属。新建分类、字段、辅助标签和关系时分配新 UUID，记录模板行 key 与实体 ID 的映射。

- 重命名分类不丢预算绑定，不按显示名重新猜测匹配。
- 一个预算方案内，同一分类只保留一条直接预算；父子预算以明确父额度约束，汇总时不重复相加。
- 一个账本可有多个月份方案，同账本同月份只允许一个当前生效方案，其他是草稿或已归档版本。
- 每个方案可复制、改名、增删分配项、改规则、保存新修订及回看旧版。
- 删除分类、存钱账本或字段时列出预算引用，用户迁移、解绑或归档后再删除。
- 模板实例与系统模板版本解耦；系统模板更新不改用户实例、历史预算或已发生明细。
- 用户可将自己调整后的方案“另存为个人模板”，自行命名；个人模板支持增删改查，不包含真实交易与隐私备注。
- 选择模板创建是事务操作，失败时回滚全部账本、分类、预算及映射；重复提交不重复创建。
- 对已有账本应用模板是显式操作，先预览分类映射/新增项与影响，只新增结构和预算，不覆盖既有交易；默认不自动套用。

### 4.1 tag余额与负数提示

每个预算tag展示：初始额度、已转入、已转出、实际使用、当前余额。单位均为分。

**tag余额 = 初始额度 + 从其他tag扣来金额 − 被其他tag扣走金额 − 实际净使用。**

- 用户录入消费超过本tag可用额度时，正常保存原金额，弹出“本tag已超支×元”提示并标红负余额。不能把支出改小、改成负支出或直接拒绝真实记账。
- 初始额度是用户配置的业务上限；超支后的负数表示缺口，不是系统漏记或新增收入。
- 仅主分类或预算tag承担额度，辅助标签继续用于查询，不因同一消费多个辅助标签而重复扣额。
- 父子分类的上层余额来自子项及直属桶汇总，只能在互斥可分配桶之间补足，不能选目标的祖先或后代制造循环余额。
- 长期储蓄预算tag若有尚未实际存入的计划余额，可由用户明确选择扣除；已经手动存入目标账本的金额属于已使用额度，不能再次当作可用预算扣走。
- 一般收入不自动冲减某tag消费。退款或取消已存入计划的释放必须关联原记录、校验金额，避免任意收入伪装成退款恢复额度。

### 4.2 点击负余额tag，从其他tag扣除

操作顺序：点击负余额tag → 展示缺口及可扣来源tag → 用户选择一个或多个正余额tag → 填每个扣除金额 → 预览双方余额 → 确认保存。

**这是实际扣减其他tag的可用余额，并补足负数tag，不是只改一个显示额度。**

示例：交通初始800元、实际支出900元，余额−100元；娱乐初始500元、未消费，余额500元。选择从娱乐扣100元后：

| tag | 初始额度 | 转入 | 转出 | 实际消费 | 当前余额 |
| --- | --- | --- | --- | --- | --- |
| 交通 | 800 | 100 | 0 | 900 | 0 |
| 娱乐 | 500 | 0 | 100 | 0 | 400 |
| 合计 | 1,300 | 100 | 100 | 900 | 400 |

- 确认前不能自动扣。可扣来源必须是同一账本、同一预算期、同币种且当前余额大于0的其他独立tag；一期不跨账本/跨月补贴。
- 每个来源扣额大于0且不超过它当前可用余额，总扣额不超过目标缺口；可部分补足，剩余缺口继续显示负数。
- 来源合计不足时仍保留真实账单与缺口，用户可扣除已有正余额的一部分，不凭空补钱，也不让来源因本操作再变负。
- 如工资总池尚有未分配余额，用户先明确分配为一个可用预算桶，再作为扣除来源；不能暗中挪用未分配额。
- 调剂本身不新增支出/收入，不修改原消费所属tag，也不把“转入预算”统计为工资收入。原始900元消费仍能追溯交通分类。
- 调剂前后所有tag余额加未分配余额之和相同；没有真实收支变化时，总剩余金额必须保持一致。
- 每次保存来源tag、目标tag、金额、账本、月份、时间、可选备注、操作ID与前后余额。双方详情均可查看，不只保留最终数字。
- 多来源扣除在同一事务中重新检查余额并整体提交，重复点击或重试用操作ID保证只扣一次。
- 允许用户撤销自己的调剂，保留反向记录及历史；撤销前校验资金去向与余额，若会让原目标再次变负须明确提示。撤销也不改变真实消费，不能删除审计痕迹。
- 消费修改、删除、退款或恢复后按事实记录重新计算余额，既有扣额不自动退回来源；如需退回由用户明确撤销或反向调剂。预算修订同样不得抹除调剂历史。

## 五、Excel 导出

### 5.1 文件类型与视图

导出真实 `.xlsx` 文件，通过 Android 系统分享/另存对话框保存。CSV 可作为附加选项，但不能把 CSV 改扩展名冒充 Excel。

| 工作表或视图 | 内容 |
| --- | --- |
| 工资分配对照 | 项目为行，用户实际创建的方案/月份为列，使用“金额｜占比”形式；仅有一份方案就导出一列，不伪造8档工资 |
| 金额及占比数据 | 将用户方案的金额、百分比拆成数值列，保留可计算能力 |
| 当前预算 | 用户命名、月份、工资、各项规则/参数/派生金额/占比及消费与储蓄汇总 |
| 实际明细（选导） | 明细 ID、账本、完整分类路径、日期、方向、金额、备注、辅助标签及选中的自定义字段 |
| 预算执行 | 各tag初始额度、转入、转出、实际使用、当前余额，保留负数；支出与存钱分开 |
| tag扣额记录 | 来源tag、目标tag、扣额、时间、操作ID、备注及撤销状态 |

“金额｜占比”单元格是展示视图，支持文本拼接；可计算数据页必须保留金额和比例为数值。Excel 中金额用格式控制显示，比例使用 `0.00%`。避免只导出一堆不可计算字符串。

### 5.2 导出约束

- 导出冻结名称列与必要表头，足够列宽，清晰区分输入、公式、汇总和来源。
- 当前预算规则属于支持范围时导出可重算公式；无法映射的规则则导出明确标记的派生快照与规则说明，不伪造可编辑公式。
- 工作簿记录模板版本、预算修订、导出时间、币种和查询范围，导出前取得一致性读快照。
- 实际交易仅导出已选择范围，按明细 ID 去重；自定义字段按定义 ID 展开，辅助标签集中展示，不因标签 JOIN 重复行。
- 名称中的非法工作表字符、长度、重复标题有稳定的转义和去重规则；用户正文以文本写入，不能被解释成 Excel 公式。
- 第一阶段验证Node.js服务端XLSX库、内存、许可证与PG一致性快照；手机通过认证API下载并分享，不直连PG。
- 大数据量按批次处理并显示进度，支持取消，失败不改源数据、不留下被误认为成功的残缺文件。
- 一期只导出，编辑 Excel 后导入回写账本不纳入范围；完整备份仍是恢复系统数据的正式方式。

## 六、数据模型补充

| 表 | 作用 |
| --- | --- |
| ledger_templates | 系统/个人模板 ID、版本、类型、配置、来源、状态；系统预设只读，修改另存个人模板 |
| template_instances | 模板版本快照、用户命名、创建幂等键、所生成账本 ID |
| template_entity_mappings | 实例、模板行 key、实际实体 UUID，避免名称匹配 |
| budget_plans | 所属账本、月份、基数、来源收入引用、状态、修订 |
| budget_items | 方案、父项、分类或储蓄去向引用、用途、固定/比例/剩余模式及参数 |
| budget_transfers | 方案、来源预算tag、目标预算tag、整数分金额、操作批次、备注、前后余额、撤销引用 |
| budget_revisions | 不可变规则与结果快照，保存历史方案 |
| export_jobs | 导出范围、状态与临时文件信息；不存一份替代事实数据的永久金额 |

预算方案与预算项进入统一 entities 注册，支持标签与适用的自定义字段/关系，但不作为实际明细挂入主树。系统模板定义属于配置，不允许通过改配置绕开金额约束。

预算派生值是可重算结果，实际金额只来自 transactions；导出复用相同领域计算服务。领域服务不得直接写数据库或自动执行交易。

## 七、一期增加的验收标准

1. 默认无勾选模板，空白账本可直接逐笔记账，不填写工资也能正常使用。
2. 模板库显示 5 种模板；选模板、输入参数、自定义名称、预览后可创建使用。
3. 工资模板只预备tag，参考工资与金额不写入用户数据；任意正数可支配工资可用，不按参考档位套用。
4. 用户自填金额与比例、零值、剩余权重、未分配、初始超分配、实际超支及到分计算分别验证。
5. 用户增删“长期储蓄”等预算项、改标签名称、换存钱去向后，绑定正确，不改真实流水。
6. 同一模板创建多个不同名称实例互不影响；重复提交不重复创建，模板升级不覆盖用户数据。
7. 52周目标和逐周金额正确，实际确认前进度为 0；应急金剩余月数、已达标和零月存额正确处理。
8. Excel 为“项目×用户方案/月份”的形式，金额和占比为数值；实际使用、调入调出、负余额与系统一致。
9. 修改导出预算中支持的输入后公式重算，不伪造实际账单；说明Excel修改不自动回写应用。
10. 导出明细按 ID 去重，长备注、中文、特殊字符、权限取消、大批量导出与异常失败均不破坏业务数据。
11. 全部模板、预算修订、映射、个人模板及tag扣额记录纳入备份，恢复后双方余额与实际明细口径不变。
12. 交通−100、娱乐500，从娱乐扣100后分别为0、400；900元真实消费和400元总剩余均不变。
13. 多来源、部分补足、来源不足、重试重复提交、消费事后修改、调剂撤销均保持流水与预算守恒。

## 八、开发顺序与工作量

先实现模板结构及纯计算 → 用户工资与分配输入 → 预算/树映射 → 模板命名预览 → 实际消费扣额及负数提示 → 点击负tag从其他tag扣除 → 导出与恢复验收。

完整第一期按 **16～22 周、80～108 人日** 估算，已包含模板、负tag扣额、动态字段/关系、Excel、备份、验收和缓冲，不重复叠加旧排期。分项工作量以实施计划M0～M9为准。示例工作簿与纯计算测试通过不等同于服务端导出及手机下载已经实现。

模板与导出接口按账号授权：普通用户只访问自己的实例及个人模板；系统超级管理员管理全部用户数据和系统模板版本。实例不因模板更新被覆盖，跨用户下载和全局模板管理写入系统审计。
