# 类别单行展示与工资收入

更新日期：2026-11-04。移动端 0.1.10 / versionCode 11。

## 类别与图标

工资模板升级为第 3 版，名称为“工资分配”。默认消费类别均不超过 5 个字：“社交娱乐购物”改为“娱乐购物”，“换季衣服鞋子”改为“衣服鞋子”，“短途出行旅行”改为“出行旅行”。分类键不变。

记一笔的图标仍使用共享图标库。图标下名称固定单行、超出宽度显示省略号，所有类别文字使用相同高度，避免长名称改变同一行图标的位置。用户自定义名称继续完整保存，不强制截断或改名；按钮的无障碍名称保留全文。类别管理列表同样单行省略。

## 工资与实际流水

按用户确认的规则，每个账本每个月关联一笔工资收入。工资模板设置页将“可支配总额”改为“工资”，增加工资日期。保存时在同一数据库事务中保存工资收入和预算；工资日期属于当前设置月份，不能晚于今天。

- 选择模板时只预备类别与预算草稿，不生成示例收入。确认工资后才创建真实收入，明细、收入统计、结余与 Excel 使用同一笔流水。
- 同月再次设置工资更新原流水 ID；网络重试幂等，不重复入账。只修改类别上限不会生成另一笔工资。
- 工资类别按 ID 绑定，使用共享 `salary` 图标。用户自行创建的同名类别不会被合并或复用。
- 从明细修改该工资的金额，会同步工资计算基数和百分比预算。工资降低到小于固定预算时保留原预算额度，剩余池派生金额为 0，不阻止真实收入修改。
- 类别固定额度可以高于工资，工资百分比仍以原始工资计算。剩余分配沿用“工资 − 固定额度 − 工资百分比额度”的计算口径。
- 可先保存工资，未填写的类别额度保留待设置。预算尚未完成不影响手动记录真实收支。收入类别不展示消费上限组件。
- 删除工资类别会按现有软删除规则移除所属工资流水。用户明确重新保存工资时创建新 ID，不恢复旧删除数据。将工资流水改到其他账本、月份或方向，会解除原关联，原类别预算保留。

普通空白账本的预算设置不自动产生工资收入；收入仍由用户逐笔记录。迁移 017 仅建立关联和约束，不将旧模板参考数据转换为历史真实流水。
