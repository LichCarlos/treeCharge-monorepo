# 账本路由与月度预算交互优化

更新日期：2026-11-04。移动端 0.1.11 / versionCode 12。

## 页面与返回关系

模块首页 → 账本管理 → 收支明细 → 月度预算。侧边导航和面包屑共用同一棵路由树。模块卡片每次都进入账本管理首页；收支明细返回账本管理，月度预算返回收支明细，类别历史返回明细列表。进入页面、切换账本和列表时滚动回顶部。

账本首页以大卡片突出“收支明细”，优先于期间汇总展示，避免小屏首屏看不到核心入口。账本切换、类别字典为次级操作；具体记录、单类别额度和预算分配的操作分别保留在各自上下文。首页不再重复展示日期筛选，明细、统计和月度预算保留对应日期控件。

## 明细与月度预算

明细页提供收支流水、类别额度、收入明细三个视图。类别额度展示当前账本所有支出类别，包括未设置额度及没有消费的类别；进度表示实际净使用金额占该类别调整后额度的比例，超支时进度条封顶、文字保留超支比例和负余额。收入类别列出名称与图标，不显示额度。

点击类别进入该类别全部日期流水，没有 200 条展示截断，按日期升序排列；收入明细同样查询当前账本全部日期的收入。点击具体流水仍编辑该笔记录。

“月度预算管理”入口位于收支明细。预算页复用 `CategoryDetailsList`，展示当前账本所选月份的全部支出类别。移除原有重复“类别消费上限”组件、第二份预算桶列表和重复创建入口。点击类别只打开该类别的 `BudgetEditor`，只提交该类别上限；工资与分配方式保留在工资模板自己的上下文。切换月份后即使没有预算，也可以单独设置类别或录入本月工资。

## 独立额度与收入

收入类别在记一笔、明细、类别管理和月度预算中均没有消费额度入口；服务端拒绝向纯收入类别写入额度，普通预算及工资模板一致。兼用于收入和支出的类别，其额度只计算支出和关联退款，收入不消耗额度。

工资模板中已设置的固定类别额度可独立生效，不依赖工资录入或其他类别完成。未设置的类别保持待设置。每个类别按自己的账本 ID、类别 ID、月份计算消费；修改一类固定金额不覆盖其他类固定金额，不增加工资流水。工资百分比和剩余池仍按用户选择的派生规则计算；固定额度可超过工资，剩余池此时为零。

迁移 `018_independent_category_caps` 使部分设置预算的消费投影和手动调剂保持一致，未设置额度不能充当调剂来源。超支仍保存真实消费；调剂由用户明确操作，并保留原有记录。

## 安全区与组件复用

主应用使用 `react-native-safe-area-context` 的 Provider 和 SafeAreaView，安全区之外增加 8dp 顶部留白。记账、类别管理沿用各自原生弹窗安全区并补齐间距；抽屉使用相同安全区实现；通用表单和操作弹窗由 `ModalPanel` 处理上下边缘，日期面板和账本选择补齐安全区。

共用类别图标库、主题色、`CategoryAllowanceBar`、`CategoryDetailsList`、`BudgetEditor` 和预算共享状态，不新增独立的额度缓存或预算表单副本。保留 Android 备注键盘收起后的高度恢复逻辑。
