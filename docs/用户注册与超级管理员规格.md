# 用户注册与系统超级管理员规格

版本：V1.0 · 2026 年 11 月 1 日

本需求纳入第一期，替代此前“仅部署创建个人账号、不开放注册”的约定。Expo访问认证API，业务数据保存在47.109.181.69的PostgreSQL。角色分为普通用户`user`和系统超级管理员`super_admin`；角色由服务端核验，系统管理员不是PG超级用户或SSH账号。

## 一、权限与管理范围

| 能力 | 普通用户 | 系统超级管理员 |
| --- | --- | --- |
| 注册、登录、退出、修改自己密码 | 支持 | 支持；管理员身份不能从注册表单选择 |
| 个人工作区的树、账本、分类、收支、备注 | 自己拥有的工作区增删改查 | 全部用户全部工作区增删改查 |
| 标签、字段定义/选项/值、附加关系 | 自己工作区增删改查 | 全部用户增删改查 |
| 计划、存钱目标、来源、退款、预算、扣额 | 自己工作区内按业务规则操作 | 可跨用户执行所有同类操作 |
| 模板 | 查看系统模板，管理自己的个人模板 | 系统模板及全部个人模板增删改查、发布版本和下架 |
| 导出、回收站、恢复 | 自己工作区 | 全部用户工作区，可按用户/工作区筛选 |
| 用户账号 | 查看/修改个人资料 | 新建、搜索查看、编辑、停用启用、重置密码、删除恢复 |
| 系统角色、全局配置 | 无 | 管理用户角色、注册开关及全局配置 |
| 系统操作记录 | 查看自己相关业务历史 | 查看全部系统/业务操作审计与管理员操作历史 |

超级管理员的“全部数据增删改查”包括跨用户业务操作，不局限于只读报表或账号管理。查看明细、编辑金额/分类/日期、移动子树、删除账本、恢复记录、管理字段、撤销扣额等均由管理入口调用相应业务用例。全局查询按用户、工作区、账本、时间及实体类型筛选，可下钻原始数据。

管理员操作同样保持外键、主树、金额精度和预算一致性。删除默认可恢复，彻底删除必须预览整批影响；存在退款、来源分配、扣额和必选关系时提供受控解绑/迁移/反向修正流程。账务更正可以改变最终业务数据，并保留修改前后值；不可变历史通过追加更正记录解释。全局审计不因业务记录删除而消失。密码字段采用设置/重置操作，查询不返回明文密码、密码散列或刷新令牌。上述规则不减少管理员对业务数据的管理范围。

## 二、用户注册与个人账号

### 2.1 页面与流程

启动检查本机登录状态；未登录显示登录页及注册入口。注册填写用户名、密码、确认密码。默认一期使用用户名注册，不绑定手机、邮箱或第三方登录，不引入短信/邮件服务。

- 用户名去首尾空格，3～32字符，拒绝控制字符；按大小写不敏感规则唯一。`system_admin`保留，不回收已删除账号用户名。
- 密码12～128字符，允许中文、空格和符号，不静默截断；确认密码仅用于前端校验，不入库或日志。
- API对请求体做严格白名单验证；注册提交`role`、`systemRole`、`workspaceId`等字段应拒绝，不允许客户端指定权限。
- 服务端使用随机16字节盐、scrypt N=16384/r=8/p=1、64字节派生密钥，存带参数的版本化编码。密码验证采用恒定时间比较。HTTPS是正式环境前提。
- 用户、空工作区、唯一根节点、owner绑定、默认手动记账设置在一个PG事务创建；失败整批回滚。
- 注册后不创建个人账本、不生成工资或实际流水、不自动套模板。显示成功后返回登录页，用户登录进入原定模块首页。
- 重复用户名返回可理解的冲突提示，前端禁止重复点击；超时不能宣称注册失败已回滚，可引导登录/核查，不能无限自动重试注册。
- 注册/登录按IP与规范化用户名限速，超限429。公开注册对所有未认证访问开放，但只有普通用户身份；管理员可关闭注册，关闭时显示明确状态，默认启用。

### 2.2 登录、修改和恢复

账号被停用或删除时禁止登录、刷新和继续业务请求。登录验证成功再签发短期访问凭据及可撤销刷新会话；每次请求验证实时账号状态和auth_version，不能只检查JWT签名。用户修改密码验证旧密码；管理员重置生成临时凭据并强制下次改密。密码/角色/启停/删除变化撤销已有会话并递增auth_version。

一期忘记密码由超级管理员重置，不提供未经验证的用户名自助找回。首次管理员登录和被重置密码的用户，只允许修改密码、查看有限账号状态与退出，改密成功后重新登录才获得业务权限。手机令牌保存在SecureStore，退出删除令牌和当前账号读取缓存；未提交草稿按用户隔离，不能切换账号后泄露。

## 三、超级管理员与管理界面

### 3.1 初始账号

服务器已创建`system_admin`超级管理员，`must_change_password=true`。随机初始密码仅存`/etc/charge/bootstrap-admin.credentials`，权限0600；没有默认固定密码、硬编码口令或把密码放入APK。拥有服务器权限的部署管理员可在SSH会话读取，首次使用后改密并移除已失效的初始凭据文件。

初始化脚本`server/ops/bootstrap-admin.py`在已有有效超级管理员时不重置、不新增。注册不能创建管理员；后续管理员可授权已有普通用户，至少保留一名未停用且未删除的超级管理员。并发降级/停用/删除使用全局账号事务锁防止两名管理员同时把系统锁死。

### 3.2 页面清单

保留原账本/笔记模块首页；登录与注册是身份前置。全部登录后页面继续提供抽屉按钮；普通用户抽屉没有系统管理入口，超级管理员增加以下入口：

```text
系统管理
├─ 用户管理：搜索、创建、资料、角色、启停、重置、删除恢复
├─ 全部数据：用户/工作区/账本选择，树、平铺及原业务详情
├─ 模板管理：系统模板版本、发布下架、个人模板归属
├─ 回收站与导出：跨用户查询、影响预览、删除恢复、授权下载
├─ 全局设置：注册开关、系统参数
└─ 操作审计：操作者、数据所属人、对象、理由、前后值、时间
```

管理员正在操作其他用户数据时持续显示“系统管理 / 数据所属用户 / 当前工作区”，不得只切本机筛选状态却调用另一个工作区。修改/删除/重置/角色调整等管理操作填写理由，确认页展示所属人及影响范围；成功反馈包含操作编号。不能把前端隐藏入口当作授权。

## 四、API与服务端授权（待实现）

| 路由 | 权限与行为 |
| --- | --- |
| GET /v1/auth/registration-status | 未登录可读注册是否开启 |
| POST /v1/auth/register | 未登录、限速、仅用户名/密码、固定普通用户、原子建工作区 |
| POST /v1/auth/login、refresh、logout | 核验账号状态、auth_version、会话撤销 |
| GET/PATCH /v1/me | 个人安全资料，不返回散列/令牌 |
| POST /v1/me/password | 验证原密码或受限首次登录凭据，更改并撤销旧会话 |
| GET/POST /v1/admin/users | 超级管理员查看全部账号/创建账号 |
| GET/PATCH/DELETE /v1/admin/users/:id | 查看资料、改角色/启停、软删除；拒绝最后管理员失效 |
| POST /v1/admin/users/:id/restore、reset-password | 恢复、临时密码重置、强制改密与审计 |
| GET /v1/admin/workspaces、entities、transactions | 跨用户分页检索与下钻 |
| 原有 /v1/workspaces/:id/业务路由 | owner处理自己的；超级管理员可处理任何存在的工作区，走同一业务服务 |
| /v1/admin/templates | 系统模板版本创建、查询、更新草稿、发布下架、删除影响预览 |
| /v1/admin/settings、audit-events | 全局配置增删改查、只追加操作历史查询 |

中央AuthService从验证后的会话构造actor，不能从请求体信任actorId、userId或superAdmin。先验证账号状态及改密限制，再按`system_role`和工作区成员角色授权。管理员绕过“必须是该工作区成员”的限制，但不绕过业务完整性校验。

服务层对详情、列表、聚合、附件/导出下载、回收站、模板和后台任务统一授权。普通用户跨用户请求统一拒绝，列表从受授权范围构造查询，不允许先取全量再前端过滤。任务执行时再次验证权限；角色变化后不继续凭旧令牌跑管理任务。

管理员写操作记录真实操作者、目标用户、工作区、对象、操作、理由及脱敏前后值，不能把操作者替换为数据所属人。批量操作有operationId、行数/金额/关系影响预览、事务与取消策略。客户端不接收数据库密码；API服务仍用受限charge_app，不把APP超级管理员映射为PG SUPERUSER。

## 五、已落实的数据库基础

追加迁移`006_registration_and_system_admin.sql`，不修改001～005历史脚本：

- app_users增加system_role、deleted_at、must_change_password、auth_version、updated_at及规范化用户名唯一索引。
- 新增system_audit_events，跨工作区记录注册、管理员账号操作与安全事件，不存密码/散列/令牌。
- register_account固定创建普通用户及空工作区；普通数据库运行账号不能直接写app_users提权。
- has_workspace_access提供用户/超级管理员作用域判定；改密限制和停用删除状态参与判定。
- admin_update_account、admin_reset_password、change_account_password提供受控账号写入与会话撤销。
- 最后有效管理员保护与账号变更事务锁；初始管理员使用独立服务端管理脚本创建。

这些数据库函数供可信API调用，参数actor必须来自已认证上下文。共享charge_app本身不是每个终端用户的数据库身份；此阶段没有逐路由HTTP鉴权，也不能凭函数测试宣称整个接口已防越权。业务管理员CRUD将复用各模块服务；当前尚无可登录注册的HTTP服务或管理页面。
