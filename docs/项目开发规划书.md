全局切换按钮 → 侧边抽屉
├─ 返回首页

│  ├─ 存钱计划账本

跳转前保存编辑草稿，草稿不计入账目；保存失败时保留输入并提示。系统文件选择器等界面遵循 Android 导航，返回应用后恢复状态。

## 三、核心数据结构

```text
工作区根
├─ 个人账本分组
│  ├─ 日常生活〔支出账本〕
│  │  ├─ 餐饮〔消费类型主标签〕
│  │  │  ├─ 早餐〔子主标签〕
│  │  │  │  └─ 支出明细：15 元
│  │  │  │     └─ 备注：豆浆、包子〔可选，最多一条〕
│  │  │  └─ 支出明细：80 元
│  │  └─ 工资〔主标签〕
│  │     └─ 收入明细：5,000 元
│  └─ 买电脑〔存钱计划账本，目标 8,000 元〕
│     ├─ 工资存入〔主标签〕
│     │  └─ 存入明细：1,000 元
│     └─ 临时取出〔主标签〕
│        └─ 取出明细：200 元
└─ 旅行账本分组
   └─ 旅行〔支出账本〕
      └─ 交通〔主标签〕
         └─ 支出明细：186 元
```

根以外的结构节点只有一个父节点，子节点数量不固定，分组与分类支持继续细分。一个分类下允许同时存在子分类和直属明细。

- 树确定唯一归属与可相加的层级统计，每条明细沿父链追溯分类、账本和分组。
- 消费类型主标签就是分类节点，和直属明细为一对多关系。
- 备注与明细为可选一对一关系。
- 辅助标签用于跨树查询，如旅行、报销、家庭；一个实体可绑定多个辅助标签。
- 附加关系支持用户配置一对一、一对多，不改变主树父子关系。
- 移动、改名、修改账目保留关键操作历史；当前报表按当前分类结构分组，历史路径可追溯。

## 四、用户管理与灵活性

账本、分组、主分类、辅助标签、明细、备注、字段定义和附加关系均提供增删改查，支持排序、移动、归档与恢复。

用户可创建文本、数字、金额、日期、布尔、单选、多选和实体引用字段，配置适用实体、作用域、必填、默认值、排序和筛选。删除字段保留历史值，改类型先预览转换冲突；一对一、一对多关系提供双向查看、修改和解绑。

金额、方向、日期和唯一归属属于账务完整性所需的基础字段，用户可改展示名、填写及修改值；系统保留内部字段键与有效性校验。UUID、父链约束和审计时间不作为可任意删除的业务字段。自定义实体“种类”、脚本公式、任意 SQL、任意图表编辑器不属于第一期。

### 可选模板与预算

默认不选择模板、不录入工资，继续逐笔手动管理。主动选模板后，填写必需参数、自行命名、预览生成结构，即可创建。提供：我的工资分配、50/30/20 比例分配、月度信封预算、52周递增存钱、应急备用金。

工资分配仅参考用户表格预备分类tag，不导入参考工资、金额、比例或合计，不做工资档位插值。用户输入自己的可支配工资并设置金额、比例或剩余规则，可新增储蓄项。

实际消费超出某tag额度时正常保存，提示并显示负余额。用户点击负余额tag，明确选择从其他正余额tag扣除金额，补足缺口；记录双方调入调出，原始收支不变，总剩余额度守恒，可部分补足或多来源扣除。

派生预算不创建实际收入、支出或存入。模板实例可编辑并另存个人模板，升级不覆盖已有方案。预算公式仅限内置受控规则，不开放脚本。增加真正的 `.xlsx` 导出，既提供“金额｜占比”展示，也保留数值金额、数值比例与公式，支持按用户所示工资对照排版。

## 五、聚合与统计

树形管理、平铺明细、同层级比较与同标签查询复用同一筛选模型。支持选定整树或子树、账本、相对层级、主分类、辅助标签、日期、方向、自定义字段和附加关系条件。

先取得唯一有效明细集合再聚合，避免一个明细绑定多个标签后重复算钱。同层级统计补足分类直属明细和未细分分支，不漏账。

支出趋势、月度分类占比、同层级对比、标签对比和存钱进度均可下钻明细。辅助标签可能重叠，用条形图或表格并标注；饼图只使用互斥主分类。支出账本与存钱账本分面显示，不把存入再算作收入。

## 六、技术架构

采用“通用树节点 + 强类型业务表 + 动态字段元数据 + 标签与关系表”。服务器PostgreSQL是业务事实来源，Zustand等仅保存界面状态。Expo经HTTPS调用Node.js/TypeScript API，服务端通过pg连接池与业务服务写入，跨节点移动、计划确认、分配、删除和恢复均在事务内校验。

主树用父节点 ID 组织，通过递归 CTE 查询，必要时增加可重建路径索引。金额使用整数分，自定义字段按类型持久化和索引。统一实体 ID 支撑标签与附加关系，不将全部数据堆入一份 JSON。

Android 使用 Development Build 验证原生能力，最终输出签名 APK。完整备份包含树、业务记录、字段、选项、标签、关系、模板实例、预算修订、审计和设置。XLSX由服务端基于一致性快照生成，手机认证下载后分享；验证服务端内存、鉴权与下载取消。第一期不引入日历、相机等仅供第二期使用的原生依赖或权限。

## 八、第二期需求保留

第二期保留以下已提出需求：

1. 备忘录、日程规划、学习笔记等类型及独立处理状态。
2. Markdown、预览、自动保存、手动相册/文件/拍照插图及服务端持久化与手机附件缓存。
3. 双链、反向链接、重命名维护、中文搜索。
4. 一篇笔记可附加多条日程，支持定时、全天、地点和提醒。
5. 首次授权选手机日历，后续一键添加、防重复和手动更新。
6. 复用标签、字段、附加关系基础设施，支持关联账本及明细。

第二期单独估时。当前先完成“模块首页 → 全局抽屉 → 账本树 → 分类 → 明细 → 路径追溯”的原型和模型验证，再按里程碑实现字段、关系与聚合。
